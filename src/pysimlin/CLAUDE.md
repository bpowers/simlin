# pysimlin

Python bindings for the simulation engine via CFFI. Exposes full engine functionality in idiomatic Python, targeting AI agents for model analysis, calibration, etc.

For global development standards, see the root [CLAUDE.md](/CLAUDE.md).
For build/test/lint commands, see [docs/dev/commands.md](/docs/dev/commands.md).
For Python-specific standards (thread safety, lock ordering), see [docs/dev/python.md](/docs/dev/python.md).

## Key Files

- `simlin/project.py` -- `Project` wrapper class (main API). Also the imperative shell for file-backed projects: `Project.open()` / `simlin.open()`, `path`/`format`/`revision`/`dirty`/`autosave`/`writable`, `save()`/`save_as()`/`reload()`/`watch()`/`on_change()`. The path is anchored absolute (`_anchor`: `Path.absolute()`, not `resolve()`, so `path` keeps the name the user gave) when adopted by `open()`/`save_as()`, never re-resolved against a later CWD. A read-only suffix (`.vpm`/`.proto`, `_formats.is_read_only_suffix` -- the same rule `resolve_write_format` applies to `save_as()`) is opened with `_path_writable=False`: `writable`/`autosave` read `False`, `autosave = True` raises, `save()` refuses (`force` does not override), every accepted change -- including the layout `_ensure_view` commits for a display -- is `MarkDirty`, and `save_as()` to a writable target (or with an explicit `format=`) sets `_path_writable=True`, after which the caller's autosave wish (`_autosave`, kept separately from the effective `_autosave_effective_locked()`) applies again. `close()` detaches the watcher and sets `_closed` in ONE `_file_lock` section and retires the watcher after releasing it, so a concurrent `watch(True)` (which checks `_closed` under the same lock) can never leave a poll thread alive past the close. Every accepted mutation funnels through `_apply_patch_json` (or `auto_layout`) into `_commit_change_locked` (bump revision, invalidate model caches, autosave) followed by `_notify` AFTER `_file_lock` is released -- new mutation paths must go through it, not around it, and must never notify under the lock. `_apply_patch_json(expected_revision=)` rejects an `edit()` whose base revision moved; `_apply_snapshot(json, base)` is the widget's entry (accept = replace in place + commit; `False` on a stale base; raises `SimlinRuntimeError` on a parse failure with nothing changed, and `SimlinWriteError` for ANY failure after the commit point (contents replaced, revision bumped): the autosave write (`write_failed=True`; dirty stays set) or notifying subscribers (a dispatcher raising on a closed kernel loop; `write_failed=False`) -- distinct types because the widget replies `rejected` to a parse failure (nothing applied) and `saved` plus a warning to a `SimlinWriteError` (applied; the type alone says the change is real, and a raw exception from past the commit point would make the widget reply `rejected` for a real change and wedge its view)) and `_snapshot()` returns the (contents, revision) pair under `_file_lock` so a widget never seeds the browser with a torn pair; `_write_to` refuses to overwrite a file another tool changed (`save(force=True)` overrides); the poll thread's delivery is re-verified against the current watcher/path/bytes in `_ingest_disk_bytes`. After variable ops the engine's incremental layout keeps a diagram in step when there is one to keep -- any file-backed project (mirroring simlin-mcp-core's `edit_model`, full layout when the model has no view yet) or an in-memory model that has a view; a diagram-less in-memory model deliberately stays diagram-less until `auto_layout()` or `_ensure_view()` (what a `ModelWidget` calls before seeding, since the Editor mounts `views[0]` and is blank without it)
- `simlin/_formats.py` -- `FileFormat` and the single suffix/content -> format table shared by `load()`, `open()`, `save()`, `save_as()` (mirrors simlin-serve `format_for_path` + simlin-mcp-core JSON key sniffing), plus the read-only-suffix rule (`is_read_only_suffix`, `read_only_suffix_message`) that `resolve_write_format` and `Project.open()` both enforce. Add formats here only
- `simlin/_sync.py` -- pure sync state machine (`decide(state, event)`) for local edits, widget snapshots, disk observations, and explicit reloads; the tests enumerate every arm. `ChangeEvent`/`ChangeSource` live here
- `simlin/_disk.py` -- `content_hash`, mode-preserving `atomic_write` (tempfile + rename), and the stdlib polling `FileWatcher` (deliberately not inotify/watchfiles: one file, all filesystems incl. Colab FUSE, no native wheel)
- `simlin/diagram.py` -- `Diagram`, the `_repr_svg_` value returned by `Model.diagram()`
- `simlin/model.py` -- `Model` wrapper class; proxies `path`/`revision`/`dirty`/`save()`/`reload()` to its project, holds `selection` (written by the widget), and the display surface: `diagram()` / `_svg_mimebundle()` (static SVG), `widget()` (a fresh `ModelWidget`), and `_repr_mimebundle_` (a fresh widget's bundle merged with the SVG so static renderers show the picture). Every display creates a new widget and the model caches none of them; the imports of `simlin.widget` are lazy (`_widget_core.import_widget_module`) so `import simlin` never pays for anywidget -- which is the OPTIONAL `notebook` extra (`pip install "pysimlin[notebook]"`; the dev and e2e extras include it): without it `widget()` raises `SimlinDependencyError` (also an `ImportError`) carrying `_widget_core.install_hint()` (`%pip` under Colab) and `_repr_mimebundle_` degrades to the SVG plus a plain-text repr that carries the same message plus a `RuntimeWarning` with it, never a traceback (the warning is attributed to the user's cell by `_widget_core.user_stacklevel()`, which skips every `simlin.*` and IPython/ipykernel frame -- a bare display reaches the repr through IPython's display formatter, and a warning attributed there would name `formatters.py`, one location for every display, and be deduped for the whole kernel session; the text/plain carries the hint too because Python's once-per-location filter can still swallow a re-run of the same cell). `_widget_core.install_hint()` detects Colab exactly as anywidget does, `"google.colab.output" in sys.modules`, importing nothing. `tests/test_widget_optional.py` pins that arm by blocking the import (`sys.modules[name] = None`); every other widget test runs with the extra installed. Why an extra and why still anywidget: its chain is a couple of dozen packages that MCP/script installs never displaying a model should not carry, and a homegrown widget stack cannot replace it -- VS Code's kernel needs `import ipywidgets` and marimo needs `anywidget.AnyWidget`, so the extra is what keeps every host
- `simlin/widget.py` -- `ModelWidget(anywidget.AnyWidget)`, the imperative shell of the notebook editor. Traits `project_json`/`revision` (kernel-owned, always assigned together in one `hold_sync()`), `selection` (browser-owned, mirrored to `Model.selection`), `height`/`theme`/`read_only`. Requests and replies are custom messages, never traits: browser `{type:'wasm'}` -> bytes as the first binary buffer; browser `{type:'snapshot', id, base, json}` -> `Project._apply_snapshot` -> EXACTLY ONE reply, always, and every reply (`saved`/`rejected`, from whichever arm below, including a malformed snapshot's) echoes the request's `id` verbatim (any JSON value; omitted when the request carried none) -- the browser resolves a save only on the reply naming its request, since one model displayed in several views sees every reply in every view: applied (including a `SimlinWriteError`, where the change is real and a post-commit step failed -- the write, or notifying subscribers) -> traits `(exact json received, base+1)` in one `hold_sync()` that exits BEFORE `{type:'saved'}` is sent (+ a warn `notice` naming what failed; `model.save()` is suggested only when `write_failed`); not applied (stale base, parse failure, or a handler exception BEFORE anything applied) -> no trait writes (the project's real pair is re-pushed, a no-op when unchanged), `{type:'rejected'}` + a warn `notice`; a handler exception AFTER the snapshot applied is an ACCEPT like the write-failure case -- the exact bytes received are pushed at `base+1` (best effort) and `{type:'saved'}` is sent plus a warn `notice`, because a `rejected` there wedges the view (in the steady state the kernel's bytes equal the sent bytes, so the browser's re-seed on a reject lands on the pair it already holds and its acknowledged base stays one behind for good); a failure AFTER the reply went out (`_SnapshotProgress.replied`) sends nothing more, and a `BaseException` (KeyboardInterrupt) gets the same one reply and is then re-raised; browser `{type:'oversize', bytes}` (it refused to send a snapshot whose wire size -- the text JSON-escaped, `_widget_core.snapshot_wire_size` -- exceeds the `max_snapshot_bytes` trait, default `_widget_core.MAX_SNAPSHOT_BYTES` = 8 MiB, chosen to stay under tornado's 10 MiB `websocket_max_message_size` with only the envelope/header left to add) -> a `RuntimeWarning` on the kernel's stderr (a comm handler runs outside any cell; JupyterLab shows it in the Log Console -- the toast is what the user sees) + the same warn `notice` the browser already showed, no reply; seeding or pushing a `project_json` above the cap warns once per widget (`_warn_if_oversize`, attributed to the user's cell by `_widget_core.user_stacklevel()` -- the display, `Model.widget()` call or `edit()` block -- with IPython's display-formatter frames skipped). Subscribes to `Project.on_change` (marshalled to `shell.kernel.io_loop.add_callback` when running under ipykernel, else direct) and pushes the project's current pair plus a notice for every change that is not one of its own accepted snapshots (`_own_revisions`, a SET of the revisions its accepts produced whose notification is still queued -- ipykernel 7 handles comm messages on a subshell thread while a cell runs, so several accepts can precede the first delivery); `close()` unsubscribes. Asset delivery is resolved ONCE at import from `SIMLIN_WIDGET_ASSET` (`bundled` | `inline` | http(s) URL) into `_ASSETS`; a missing asset never breaks `import simlin` -- creating a widget raises `SimlinAssetError`. The `inline` shim contract with the JS (`globalThis.__simlinWidgetInlineWasm = "<base64>";` on the line before the module) is documented on `_widget_core.inline_esm`
- `simlin/_widget_core.py` -- the widget's pure decisions: `parse_asset_mode`/`inline_esm`/`missing_asset_message`, `parse_incoming` (message classification; malformed messages are `Unrecognised`, never exceptions), `plan_snapshot_reply` (accept / stale / raised arms), the snapshot size guard (`MAX_SNAPSHOT_BYTES` with its rationale, `snapshot_wire_size`, `oversize_warning`/`oversize_report_warning`/`oversize_notice`, `format_size` -- mirrored byte for byte by `snapshotWireSize`/`formatSize` in the JS, with one fixture list pinned in both suites), `is_own_change`, `notice_for_change` (one text per `ChangeSource`), `dispatch_for_shell`. `tests/test_widget_core.py` enumerates every arm; `tests/test_widget.py` drives the shell through a recording comm (no browser, no kernel)
- `e2e/` -- the JupyterLab journey (Playwright; design AC4.2): `global-setup.ts` launches `jupyter lab` from this venv (`jupyter-server.ts`: OS-assigned port, random token, temporary config/data/runtime/root directories, a preflight that the interpreter imports `simlin` with staged widget assets and `jupyterlab`) and hands the URL/token/root to the spec through `SIMLIN_E2E_*` env vars; `notebook-editor.spec.ts` drives the real JupyterLab UI: `simlin.open` + display -> the Editor renders; a variable added and given an equation in the Editor -> the file on disk changes and a following `m.run()` cell reports it; `m.selection` names the selected variable; a Python `edit()` -> "Updated from Python" in the Editor; a second-process write -> "Updated on disk" and `m.revision` advanced, and after those remounts `m.selection` is `()` again. It is NOT part of `pytest`/pre-commit: `make e2e` runs it (CI: the `pysimlin-e2e` job); it needs the `e2e` extra (jupyterlab, in THIS venv so its share/jupyter carries the anywidget/ipywidgets labextensions), the CFFI extension, staged `simlin/_widget/` assets (`make assets`), and Playwright's chromium. `SIMLIN_E2E_PYTHON` picks another interpreter; `SIMLIN_E2E_KEEP_TMP` keeps the server tree; the server log (jupyter-lab.log) is written to the git-ignored output directory beside the spec (see `e2e/playwright.config.ts`)
- `scripts/check_notebook_export.py` -- executes an example notebook headless with nbconvert and checks both static-export arms of the display cell: with the stored widget state the HTML carries the widget view plus the embedded state (the `_esm` rides along), and with `metadata.widgets` stripped -- what GitHub or a notebook saved without state gives a static renderer -- nbconvert's `WidgetsDataTypeFilter` skips the widget-view mimetype and the HTML carries the SVG (the lab template embeds it as a base64 `<img>`). Its pure half is unit-tested in `tests/test_check_notebook_export.py`; the shell runs under `make export-check` and the CI `pysimlin-e2e` job, never as a pytest (the dev extra has no nbconvert and a skipped test proves nothing)
- `docs/notebook-hosts.md` -- per-host checklist for the notebook editor (JupyterLab 4, Notebook 7, VS Code local/Remote-SSH, Colab, marimo) with each host's VERIFIED/UNVERIFIED status; only JupyterLab is verified (by `e2e/`). Update the status line in the same PR that runs a checklist. `examples/colab_quickstart.ipynb` is the Colab entry point (its `%pip` cell is skipped by `tests/test_examples.py`'s script run)
- `simlin/_widget/` -- package data: `widget.js` and `libsimlin-browser.wasm`, build outputs of the `@simlin/notebook-widget` TypeScript package (git-ignored; see its README.md and `pyproject.toml` package-data)
- `simlin/sim.py` -- `Sim` wrapper class (simulation runner)
- `simlin/run.py` -- High-level run utilities
- `simlin/vdf.py` -- `simlin.load_vdf(path)`: import a Vensim VDF binary output file (run, sensitivity, or dataset container, auto-detected by magic) as a `Run.results`-shaped DataFrame (time index, canonical column names, `"var[element]"` arrayed columns). A function returning a plain DataFrame, not a class: a VDF carries only named series, exactly the `Run.results` surface, and no loop/override metadata that would justify a wrapper object. Malformed files raise `SimlinRuntimeError` (the engine's VDF readers are total on arbitrary bytes; see the sweep test in [/src/simlin-engine/src/vdf.rs](/src/simlin-engine/src/vdf.rs))
- `simlin/_ffi.py` -- Low-level CFFI bindings, module-level `_finalizer_refs` with `_refs_lock`. Besides the per-call helpers (`apply_patch_json`, `serialize_json`, `render_svg`/`render_png`, ...) it carries the three primitives that reloading a project from disk is built on: `serialize_mdl(ptr) -> (bytes, list[ErrorDetail])` (Vensim export; lossiness warnings are returned, not raised, mirroring `apply_patch_json`'s collected diagnostics), `replace_contents(dst_ptr, src_ptr)` (in-place reload: `Model` objects already obtained from `dst` stay valid and observe the new contents, but the caller must run `Model._invalidate_caches()` on them; open the new bytes into a scratch project with any format and replace from it), and `diagram_sync(ptr, model_name, patch_json=None)` (a non-None applied patch selects the engine's incremental layout, which keeps existing element positions; None is a full relayout, which is what `Project.auto_layout` asks for). Tests: `tests/test_ffi.py`; the reload/serialize churn under ASan lives in `tests/test_memory.py`
- `simlin/_ffi_build.py` -- CFFI build configuration
- `simlin/types.py` -- The unified public variable types (`Stock`/`Flow`/`Aux`/`Module` + `Compat`/`ElementEquation`/`GraphicalFunction`), frozen dataclasses used for BOTH reading (`Model.get_variable`, `edit()`'s `current` dict) and writing (`patch.upsert`); edit by `dataclasses.replace` + `upsert`. There is deliberately no `uid` field (the engine preserves/mints uids on upsert, see `patch.rs::upsert_variable`); everything beyond a variable's core surface -- ACTIVE INITIAL, non-negativity, conveyor/queue markers, data sources -- lives in `Compat`, mirroring the engine's own Compat
- `simlin/json_types.py` -- Wire/patch-only dataclasses (ops, views, sim specs, project structure); variables are the unified types above
- `simlin/json_converter.py` -- Bidirectional unified-type <-> engine wire JSON mapping (`structure_variable`/`unstructure_variable`) plus cattrs config for the wire types; the variable mapping is hand-written on purpose (arrayedEquation folding, legacy-compat merging, `""`-vs-`None` normalization)
- `simlin/analysis.py` -- Model analysis functions
- `simlin/errors.py` -- Error types (`SimlinDependencyError` is both a `SimlinError` and an `ImportError`: the `notebook` extra is missing)

## Thread Safety

All wrapper classes have a per-instance lock (`Sim`'s is an `RLock` so `get_run()` can hold it across the whole Run snapshot). `Project` has a second `RLock`, `_file_lock`, for file-backing state and whole mutate-then-write sequences. Lock ordering: `Project._file_lock` -> `Project._lock` -> `Model._lock`; release `Model._lock` before calling `Project` methods; change callbacks fire with no lock held. `ModelWidget` has one lock, `_state_lock`, around its trait pushes (`_push`, one `hold_sync()` per pair) and its set of own pending revisions: which thread runs a comm handler is the kernel's choice, and ipykernel 7 (JupyterLab 4.4+) runs them on a subshell thread WHILE a cell executes, so a snapshot is applied, written, and pushed on that thread while `Project.on_change` notifications (marshalled onto the kernel IO loop with `dispatch=`) are delivered on the loop's thread after the cell. The model side is serialised by `Project._file_lock` (a snapshot vs a concurrent `edit()`: whichever comes second sees the moved revision and is rejected as stale / "project changed during edit"). `_state_lock` is taken with no Project lock held; it is necessarily held across the pair's own state message (the `hold_sync()` exit sends it) and never around a custom-message `send`. See [docs/dev/python.md](/docs/dev/python.md).

## Non-Standard Commands

```bash
cd src/pysimlin
uv run pytest tests/ -x     # Run tests
uv run ruff check            # Lint
uv run ruff format           # Format
uv run mypy simlin           # Type check (strict)
make assets                  # Build + stage the notebook widget assets into simlin/_widget/
make check-assets            # Verify the staged assets against ASSETS.json
make e2e                     # JupyterLab notebook journey (Playwright; not in pre-commit)
make export-check            # nbconvert the example notebook: widget view with stored state, SVG without (not in pre-commit)
uv run python scripts/build_wheels.py   # libsimlin + assets + wheel (see DEVELOPMENT.md)
```

The widget assets (`simlin/_widget/widget.js`, `libsimlin-browser.wasm`, `ASSETS.json`) are build outputs, staged only by `scripts/stage_widget_assets.py` (the notebook-widget package's `pnpm build` calls it too); `setup.py` refuses to build a wheel/sdist without them and `scripts/check_wheel_assets.py` is the release workflow's wheel-content check. Details: [DEVELOPMENT.md](/src/pysimlin/DEVELOPMENT.md).
