# simlin-engine

The simulation engine: it parses, lowers, type-checks, unit-checks, compiles, and simulates system dynamics models.
The root `CLAUDE.md` holds the development rules; this file is a map of where functionality lives (paths are relative to this crate's `src/`) and of the standing invariants code in this crate keeps.
It is built on [simlin-base](/src/simlin-base/CLAUDE.md): the data model, identifiers, dimensions, the equation lexer, parser and AST, and the builtin functions.
The file formats ([simlin-formats](/src/simlin-formats/CLAUDE.md)) and the edits to a project ([simlin-edit](/src/simlin-edit/CLAUDE.md)) do not depend on it, and its unit tests use both.
The diagram layout ([simlin-layout](/src/simlin-layout/CLAUDE.md)), the wasm backend ([simlin-wasmgen](/src/simlin-wasmgen/CLAUDE.md)), the [save check](/src/simlin-save-check/CLAUDE.md) and the [agent tools](/src/simlin-tools/CLAUDE.md) are built on it.
It is a map, not a history: `git log` and `git blame` are the changelog.

## Compilation pipeline

Equation text becomes a running simulation in six stages.
Each stage names its owners.
"One owner" means the only place a decision is made; a second walker, classifier, matcher or resolver for the same fact is a defect, not a convenience.

1. **Parse** (simlin-base's `lexer`, `parser` and `ast::expr0`, and `variable.rs`).
   - `Expr0::new` produces the parsed AST, a bare zero-argument builtin's name (`pi`, `time`, `dt`) as the builtin's call.
     `ast::needs_quoting` is the one statement of which names cannot be written bare when an identifier is printed back to equation text: a keyword (`lexer::KEYWORDS`, the reserved-word table) and a zero-argument builtin's name, besides a name the lexer does not read as one identifier, so a variable of such a name round-trips quoted and still reads the variable.
     Bare is the builtin and quoted is the variable at every later stage: a NAME (an equation's quoted reference, a flow list's entry, a module input's source) is only ever a variable -- to name resolution (`db::var_fragment::resolve_referenced_heads`; an undeclared one is an unknown dependency like any other), to unit checking and inference, and to LTM -- so a variable declared under a builtin's name (Vensim models declare `dt = TIME STEP`) reads as itself through its quoted name.
     The rule is the engine's own, beyond XMILE 1.0, which reserves function names (the citations are at `ast::needs_quoting`); what Vensim does with such a name is unverified, and the MDL importer quotes a reference to a variable the model declares under such a name, so it reads the variable as in Vensim, and the MDL writer writes the builtin as Vensim's keyword and the variable as its name (`src/simlin-formats/src/mdl/CLAUDE.md`).
     A variable named for a clock slot (`time`, `dt`, `initial_time`, `final_time`) takes that slot's key in the results-offset map (`VariableLayout::root_shifted` inserts the clock's keys first, then the body's), so the column of that name is the variable's series and the clock keeps its slot (`results::TIME_OFF`) with no key: a reader of the clock reads the slot, as `save_check` does.
     `ast::print_eqn_proptest` holds `parse(print_eqn(e)) == e` over every `Expr0` variant, index form and name class (`ast::expr0_strategy`).
   - `ast::CanonicalEqn` (built by `Expr0::canonical`) is the one normal form of an equation, and so the one owner of whether two equations say the same thing: no source positions, canonical idents and function names, numbers by value, and under `Aliases::Engine` the engine's own rewrites (a builtin's alias through `BuiltinSig::by_name`, `MODULO(a, b)` as `a mod b` through `ast::operator_for_call`, which the module-function expansion applies too, `PI()` and `INF()` as their constants), none of them where the project defines a macro of the name (or, for an alias, of the builtin's own name), and no constant or operator fold inside a subscript.
     It has structural `Eq` and `Hash` and prints through `print_eqn`.
     `save_check` compares equations by it and `Expr0::eq_ignoring_loc` (helper identity) is its `Aliases::Spelling` equality walked without allocation; a caller with a further notion of sameness layers it over this form rather than restating it.
   - `parse_var(&ParseContext, impl Into<VariableSource>, ..)` is the one parse entry point.
     A `VariableSource<'_>` is a BORROWED view of the fields a parse reads (ident, equation, gf, units, kind, flows, module refs and target model name, `non_negative`, `can_be_module_input`, `active_initial`), built either straight over the salsa inputs (`db::variable_source`) or from a `datamodel::Variable`.
     A `ParseContext` carries the project-global contexts (dimensions, units, the macro registry, the enclosing macro body) plus the `SnapshotIndexFacts` a `PREVIOUS`/`INIT` subscript index is decided with.
   - A source parse reads the owning model only through per-name projections (`variable_owner_model`, `model_variable_by_name`, `variable_dimensions`, `project_has_qualified_element`), never its variable set, so `db::parse_source_variable` is keyed on `(variable, project)` (the rule under "Salsa layer").
2. **Module-function expansion** (`builtins_visitor.rs`, `capture.rs`, `module_functions.rs`, `snapshot_arg.rs`).
   `instantiate_implicit_modules` rewrites stdlib calls (`SMTH1`, `DELAY3`, ...) and project macros into module instances and routes `PREVIOUS`/`INIT` to the `LoadPrev`/`LoadInitial` opcodes.
   - Everything it synthesizes is parsed data on one ordered `capture::ImplicitVar` list: a `Capture` (a `PREVIOUS`/`INIT` argument that is not a static slot) or a `HoistedArg` (a call argument that is not a bare identifier) carries the argument's `Expr0` subtree, and an `ImplicitModule` carries its target model and input-port wiring.
     `ImplicitVar::parsed_variable` is the one conversion back to a parse-stage variable, so no helper is printed and parsed back (GH #913's class).
   - `capture::synthetic_ident` is the one derivation of a helper's `$⁚{parent}⁚{n}⁚...` name (`n` shared by an instance and its arguments).
     The name is an external key the runlist, the layout and the results map sort by; `capture::insert_implicit_var` is the one rule for two helpers claiming one name (a same-definition repeat is idempotent, a different helper is `DuplicateVariable`).
   - A helper's equation errors carry spans into the PARENT's equation and are reported on the parent; a helper body the COMPILER refuses is the parent's equation error too, with the compiler's code at the argument's span (`db/fragment_compile.rs`); only a codegen refusal stays an assembly row on the helper.
   - A helper keeps its parent's element context (GH #1035).
     `per_element_requirements` decides what an apply-to-all body needs: a snapshot-only body is captured ONCE, structurally, as an apply-to-all capture over the parent's dimensions (`CaptureShape::ApplyToAll`); a module-bearing body is expanded per element, every hoisted argument (a bare arrayed identifier or dimension name included) carrying the element it is one element of (`variable::ElementScope` on `VarKind::Aux`).
     A structural capture is lowered by the apply-to-all arm (`expand_per_element`) and a per-element helper by `Context::element_scope_context`, both under the element context the parent's own body gets, so a helper reads exactly what the plain spelling reads.
     Never add a parse-time replay of the compiler's resolution rule: two resolvers of one spelling drift exactly where the rule is non-trivial.
   - A snapshot subscript naming a dimension the parent's axes relate to (a declared mapping or subdimension) reads its slot directly: `index_spans_a_dimension` asks the compiler's own matcher (`match_axes_partial` under `DirectMappingsOnly`, the projection `active_dim_ref` uses).
   - `snapshot_arg::SnapshotArg::access` is the single statement of what a `PREVIOUS`/`INIT` argument addresses (`SnapshotAccess`: slot, view, or capture), classified by this parse and by codegen (`static_slot`, `Compiler::snapshot_static_view`) alike, so the dependency graph and the bytecode cannot disagree (GH #568's class).
   - Whether an identifier subscript of such an argument pins ONE declared element is the one model-level question the parse answers itself (a capture cannot be un-minted at lowering), through `builtins_visitor::SnapshotIndexFacts`: the source parse asks the referenced variable's declared axis -- an element of that axis wins over a same-named variable, XMILE 1.0 footnote 9 and the compiler's own `dimensions::resolve_axis_index_name` -- and whether the project declares a qualified `dimension·element`; the generated LTM parse, whose target may be a synthetic variable with no declared axis, asks whether any dimension declares the element and no variable of the model shadows it.
   - What a `PREVIOUS`/`INIT` argument's NAME denotes -- a bare module instance (refused: it has no storage of its own), a bound input port (its own slot), a module output port or a plain variable (a fixed slot) -- is resolved at lowering by `compiler::context::Context::snapshot_storage` from the dependency's shape.
     The parse captures only the one module-backed name it can know without the model: an instance synthesized earlier in the same walk.
   - A capture's kind is its phase demand (`capture::CaptureKind`): `PREVIOUS` storage is refreshed in flows only, `INIT` storage is populated in initials only unless a per-step definition reads its current value, and the dt and active-initial parses minting one storage for both consumers share it with the union of the two.
   - `DELAYN`/`SMTHN` rewrite to the canonical order-1 and order-3 models and wire only the ports the call names (`rewrite_alias_module_call`): an omitted initial value is the stdlib model's `isModuleInput(initial_value)` fallback to the input, XMILE 1.0 section 3.5.3; an order other than 1 or 3 refuses.
     `DELAY` -- XMILE's infinite-order (pipeline) delay, which the MDL importer writes Vensim's `DELAY FIXED` as -- is refused there too (`NotSimulatable` on the variable): it needs a record of the input over the whole delay time, which no stdlib model holds, and a first-order delay under its name would be a silent wrong number.
     Expected results for XMILE's `DELAY` are beside a Stella Architect file in `test/test-models/tests/delay_xmile` (the input exactly one delay time back; which tool wrote them is not recorded), and Vensim's for `DELAY FIXED` in `test/sdeverywhere/models/delayfixed*` and `test/test-models/tests/delay_fixed`.
   - `MacroRegistry::resolve_call` is the one routing decision for a call (`Expand`, `Passthrough`, `RenamedBuiltinSelfCall`, `Unresolved`), read by the visitor and by macro-recursion analysis.
     A macro shadows a like-named builtin: the engine's rule, unverified against Vensim's documentation, and the opposite of XMILE 1.0 3.2.2.5, which reserves builtin names and says a conflict SHOULD be flagged.
     A genuine passthrough lowers as its builtin under the macro's arity, and the enclosing macro's own renamed builtin lowers as the builtin (GH #554).
3. **AST lowering** (simlin-base's `ast` and `builtins`, and `model.rs`).
   `Expr0` -> `Expr1` (typed `BuiltinFn`; `ast::typed_ast`) -> `Expr2` (array bounds resolved; `ast::lower_ast`).
   - `ast::LoweringScope` is what the `Expr2` lowering knows: the project's dimensions and, for every name the equation can reference, the `DepShape` the fragment compiler resolves it through (the same `FragmentInput::deps` map), so a helper lowers under its parent's shapes.
     A module output `m·x` is never a key and lowers without bounds (`compiler::Context` resolves it through the instance's shape).
     Every lowering -- a source variable's, a helper's, a generated LTM equation's -- runs under the shapes of the names it references.
   - An `Expr2` node's bounds slot is `ast::NodeBounds`, an `Option<Box<ArrayBounds>>`: the lowered trees are retained (the per-variable memos, the LTM handle maps) and a bound is `None` on every scalar subexpression, so a `None` costs one pointer.
     Readers go through `get_array_bounds`; the box is spelled only where a bound is produced.
   - `classify_dependencies` is the one dependency walk, run over the typed `Expr1` for the dependency query and over a retained `Expr2` subtree for LTM's per-slot readers, through one `DepExpr` projection per tier; it needs no scope.
     It records each read as a `DepOccurrence` with its `DepLag` (`Current`; `Previous`; `Initial` for an `INIT` argument or a `PREVIOUS` fallback) and each `LOOKUP` table holder as a typed table reference beside the reads.
   - `model::lower_variable` is the one `Expr0 -> Expr2` map over a variable's `kind`; its module arm resolves the instance's wiring through `db::build_module_inputs`, the one owner of that wiring, under the model's CANONICAL name.
   - Each variable is lowered ONCE: `db::lowered_source_variable` (explicit) and `db::lowered_implicit_variable` (a parse-synthesized helper) are the only owners of a lowered `Expr2` variable.
     The fragment borrows the memo; unit checking and the LTM describers hold its `Arc` through `db::model_lowered_variables`; no whole-model lowered copy exists.
   - `BuiltinFn::signature()` is the one statement of every per-builtin fact: name and aliases, source arity, which argument positions are array operands and whether the enclosing apply-to-all element pins their axes (`ArgKind`), the result's shape (`ResultKind`), and the invariance class (`Invariance`).
     `args()`/`args_mut()` and the `map` family are the uniform argument view.
     A match over `BuiltinFn` anywhere else encodes per-variant semantics (which opcode, which unit rule, which argument shapes the result) and says so in a comment.
4. **Per-variable fragment compilation** (`compiler/fragment.rs`, `db/var_fragment.rs`, `db/fragment_compile.rs`, `db/ltm/compile.rs`, `compiler/`).
   - `compiler::fragment::lower_fragment(&FragmentInput, is_initial)` is the one per-variable lowering entry point.
     A `FragmentInput` is the variable in its `Expr2` form plus a `DepShape` -- dimensions, and whether the name is a plain variable or a module instance -- for every name it can reference; it carries no offset of the model being compiled.
   - Four constructors: explicit variables (`explicit_fragment_input`), implicit helpers (`implicit_fragment_input`), LTM synthetic variables (`ltm_fragment_input`) and LTM implicit helpers (`ltm_implicit_fragment_input`).
     The two in-model constructors resolve dependency shapes through the per-variable firewall queries (`db::var_fragment::DeclaredName` over `model_variable_by_name`, `model_implicit_var_by_name`, `variable_dimensions`, `model_shape` for a module's sub-model, and `variable_tables` for a called table) and borrow the variable's lowering memo, so a helper the parse hoisted lowers -- and is refused -- exactly as the equation's own spelling.
   - The two LTM constructors read the whole `model.variables(db)`, `model_implicit_var_info` and `model_ltm_implicit_var_info` maps (the LTM surface they lower is itself derived from a whole-model query, `model_ltm_variables`) and share one lowering, `lower_ltm_variable`: the reads classified on the typed `Expr1`, resolved through `DepScope::resolve` to the shapes the compiler reads, and the equation lowered under that same map.
   - `lower_fragment` lowers `Expr2` -> `Expr3` (`src/simlin-base/src/ast/expr3.rs`, a structural rewrite that resolves wildcards and gives every bare array reference its subscripts) -> `compiler::Expr`: `compiler/mod.rs` expands apply-to-all and arrayed equations per element (`expand_per_element`); `compiler/context.rs` resolves references and subscripts against the dependency shapes; `compiler/subscript.rs` normalizes static subscripts into views; `compiler/fold.rs` folds constants.
   - `compiler/array_operand.rs` is the fragment's ONE materialization pass: it moves every array value codegen cannot express in place -- the array-producing builtins, the per-element arrayed-GF applies, and the computed array operands -- into temps, so codegen only ever sees views.
     It is the only caller of `ast::TempAllocator::alloc`; the allocator is owned by the `compiler::Context` the fragment lowers under and shared by every context derived from it.
   - `compiler/codegen.rs`, under the same input's `FragmentInput::emit_ctx`, emits `SymbolicOpcode`s whose variable operands are `VarRef { name, element_offset }`.
5. **Assembly** (`db/layout.rs`, `db/assemble.rs`, `compiler/symbolic.rs`).
   - `compute_layout` assigns slots per model, and `flattened_offsets` reads that layout back out as the results-offset map (`CompiledSimulation::offsets`: `module·var` through each module instance, `var[e1,e2]` per element of an arrayed variable, explicit or a structural capture helper (GH #1033), no key for a lookup-only table or for an INIT-only capture, whose slot nothing writes per step), so slot order is stated once.
   - `assemble_module` collects every fragment source -- explicit, implicit, LTM synthetic, LTM implicit -- into one map and emits each of the module's three programs in runlist order: a resolved recurrence SCC's members replaced by the SCC's combined fragment at the first member, the run-invariant flows hoisted ahead of the dynamic ones, the LTM tail after the runlist.
     It drives ONE `FragmentMerger` through them: every initial as a standalone program, then the flows and the stocks as one concatenation each.
     The merger renumbers per-fragment literal/GF/module/view/temp/dim-list ids into the module's single table set, de-duplicates graphical functions by content, and gives each program its own literal pool; `resolve_module` then turns `VarRef`s into offsets.
   - A combined fragment interleaves the members' per-element segments in the element graph's order, and `segment_member_by_element` is the one statement of where a member's code splits -- the graph and the combiner both read it.
     A member's PROLOGUE (the leading temp blocks two or more elements read, or that a later prologue block reads) is emitted once, immediately before the first of its readers in that order, and the graph wires the prologue's reads into exactly those readers, so a recurrence whose shared temp reads a non-reader element runs that element first rather than being refused.
   - `assemble_simulation` enumerates module instances (`enumerate_module_instances`: a model's explicit `Module` variables and the instances its parses synthesized, one candidate shape, each recorded under `(target model, bound-port set)`) and builds the `CompiledSimulation`.
   - A reference's port is `port_of(dst)`, and the one bound-port rule over it (`bound_port`: `port_of(dst)` when the `src` is outside the instance's namespace) is what both the instance's compilation identity (`module_input_set`) and its lowered wiring (`build_module_inputs`, at lowering) project from, so the ports a sub-model is compiled under are the ports its instance writes; a reference `bound_port` declines is dropped there without an error, which is why the wiring is validated by the diagnostic pass.
   - `model_module_wiring_diagnostics` validates `port_of(dst)` for every reference and warns about a reference to one of the instance's own ports whose `src` is inside the instance's namespace, which binds nothing (a `src` inside the namespace with a `dst` in another instance is the connect a writer records on the source instance, and the `dst` check is its report).
6. **Execution** (`vm.rs`, `bytecode.rs`, and [simlin-wasmgen](/src/simlin-wasmgen/CLAUDE.md)).
   The stack VM runs initials, then per step flows and stocks, under Euler, RK2, or RK4.
   simlin-wasmgen lowers the same `CompiledSimulation` to one self-contained wasm module that mirrors the VM opcode for opcode.
   - The run is on a step grid that `results::Specs` states once and both backends compute in the same f64 operations: the clock is counted, never accumulated (step `k` is at `Specs::time_at(k)`, `start + k * dt`); the run evaluates steps `0..=Specs::final_step()`; saved row `m` is the first step at or after its save time (`Specs::saved_row_step`), so a save step that is not a whole number of DTs keeps its declared row count and times to within a DT (the engine's rule; XMILE has no save step and what Vensim does with a SAVEPER off the TIME STEP grid is unverified) and is reported as the warning `SaveStepOffTheStepGrid`.
     A time a person writes as a step's is read as that step within `STEP_TOLERANCE` (a millionth of a step).
     Whatever finite numbers the specs hold, a run is refused with a reason or has row zero at step zero: specs no run can be made under (a stop before the start, a DT that is not positive) are refused by both backends for the one reason `Specs::refusal` gives, the save step in DTs is kept finite, and a run whose rows cannot be counted or that the allocator will not give is `BadSimSpecs`, its numbers written as a person writes them (`results::written`; the wasm blob also refuses a run of more steps than its i32 counter holds).
   - `Vm::run_to(t)` evaluates every step at or before `t` and rests at the next, unevaluated; `Vm::run_until(t)` evaluates every step before `t` and rests at the first step at or after it, which is where a caller sets a value that must hold from `t`.
     The clock never goes back: a finished run rests one step past the stop, its stocks integrated through the final step and its flows previewed, and a further call takes no step.
     The wasm blob's resting `curr` is the VM's, bit for bit, while the target is before the blob's last saved row; from there on the blob rests at that row, evaluated, and takes no step past it (with a save step over DT, not even those before the stop).
     `simlin_wasmgen::module::tests::where_a_run_rests_on_each_backend` tables both; making the blob rest where the VM does is a question of its ABI, left open.
     `Vm::with_specs` runs a compiled program under other specs: the program does not depend on them.
   - XMILE's `PULSE` fires at the first step at or after its time, read on the step grid within `STEP_TOLERANCE`, so a pulse time written as a step's is that step (`vm::pulse`, and `emit_pulse` in simlin-wasmgen's `lower.rs`).
     XMILE 1.0 section 3.5.4 says only "a one-DT wide pulse at the given time"; what Stella does with a pulse time between two steps is unverified (every PULSE in the corpus is at a step's time).
     Vensim's `PULSE(start, width)` is another function, which the MDL reader lowers to its own expression.
     `STEP` compares the clock half a step ahead.

`db::compile_project_incremental` is the single production entry point for ordinary models.
`queue_compile::compile_sim` is the dispatch every VM-backed caller goes through: a model with a conveyor or queue marker takes the special-stock path (below), anything else goes to `compile_project_incremental`.
`build_sim` is `compile_sim` plus `Vm::new`.

## Salsa layer (`db.rs`, `db/`)

`SimlinDb` owns the salsa storage, the sync state of the last synced datamodel, the expanded (conveyor/queue) twin's sync state, and the one-shot stdlib model inputs.
The inputs (`db/input.rs`) are `SourceProject`/`SourceModel`/`SourceVariable`, storing datamodel fields directly so invalidation is per field; `db::variable_source` is the parser's borrowed view of them.
`db/sync.rs` maps a `datamodel::Project` onto those inputs through one extraction per input (`SourceProjectFields`, `SourceModelFields`, `SourceVariableFields`, each a `from_datamodel`) that both the fresh-sync constructor and the incremental updater read, reusing handles across syncs and setting only fields whose value changed.
`db::simulation_key` (public: hosts compare it through libsimlin's `simlin_project_get_simulation_key` before simulating again, and the agent tools keep runs fresh by it) hashes those same extractions, and every type their fields hold, each destructured without `..`, leaving out what no run reads (units; the names and uids only a diagnostic words; a pinned loop's description; a table's y scale, and its x scale beside written x points): a field the compiler starts reading is a compile error there until the key says whether it counts, so the key cannot fall behind the sync.
`db/simulation_key_tests.rs` takes each type's field list from a pattern that must name them all (`fields!`, `variants!`) and fails for a field or variant with no row.
Text is hashed as written, so a respelled equation or a case-only rename moves the key: it may call one simulation two, never two one.
A sync state remembers the variable each input was last set from (`PersistentVariableState::synced`, by its `Arc`), so a re-sync after a patch, which shares every variable the edit left alone, extracts and compares only the variables the edit replaced (`db/sync_identity_tests.rs`).
What a pass may take from that memory is stated once, in `InputMemory`: the state must be that of the inputs' latest sync (`PersistentSyncState::is_current`; a rollback re-syncs with the state from before a staging, and compares every variable), and an input is answered for once per pass, so a second variable or a second model that shares an input (two of one canonical name) is always compared.
The standing test of the incremental sync is that a db holds, after any sequence of syncs, staged syncs and rollbacks, what a fresh db synced to the same project holds, and so answers what it answers (`db/sync_differential_tests.rs`, over a pool of projects that varies every field the sync writes: the default suite compares the inputs, the gates every diagnostic, series and loop count too).
The stdlib models' inputs are the db's own and no sync writes them: a project model named for a stdlib model has inputs of its own and stands in the stdlib model's place while the project holds it.
Two project models known by one name (`datamodel::canonical_model_name`: the canonical name, an unnamed model's being `main`) make a project refused as a model with two variables of one name is (`db::diagnostic::project_duplicate_models`: the compile gate and one project-level `DuplicateVariable` row), and `AddModel` refuses to make one.
Of several models of one canonical name the sync files only the last (`filed_models`), so re-syncing such a project makes no input.
`AddModel` also refuses a name under the stdlib's prefix: the one way a project holds a stdlib model is the stdlib's own definition, which `Project::ensure_referenced_stdlib_models` adds.
Everything else is tracked queries:

- `db/query.rs` -- per-variable parse (`parse_source_variable`), direct dependencies, dimension reads, module maps, the module-reference graph (`project_module_graph`), and the firewall queries (`model_variable_by_name`, `model_implicit_var_by_name`, `project_model_by_name`, `variable_owner_model` over the `owner_model` name the sync sets on every `SourceVariable`, `project_has_qualified_element`, `variable_tables`) that let a fragment or a parse depend on one variable, one owner, one model or one element instead of the whole map.
  - One dependency representation: `variable_direct_dependencies` owns a variable's reads as `DepRefs`, a set of `DepRef { target: DepTarget { module_path, variable, stock_output }, phase, lag }` for the variable and for each helper its parse synthesized (`ImplicitVarDeps`), plus the typed `referenced_tables`.
  - `DepScope::resolve` proves every `·` hop against metadata through the per-name projections: the head must be a module instance in scope (an explicit `Module` variable or an implicit instance), each further segment a `Module` variable of the model the previous hop instantiates, and the terminal's kind is read in the same walk (`stock_output`).
    A leading `·` is XMILE's parent-scope spelling, read as the bare name.
    A spelling that fails a hop is one local name, that `·` stripped, which the compiler refuses at lowering.
  - No consumer splits a name.
    `dep_graph::ordering_edges` is the one statement of which reads order which phase: a `Dt`/`Current` read orders the dt phase unless its target is a sub-model stock, at any depth (a prior-step read); every init read but `Previous` orders initials; `Dt`/`Initial` reads seed the initial snapshot.
    `dt_previous_only` is `Previous - Current`: an `INIT` read never cancels a lag.
    The pinned-loop and statelessness gates, the causal edges, the output-port scans, the lowering memos' `heads`, the layout and the libsimlin surface all read the projections.
  - The causal-edge builder records the sub-model outputs each node reads once (`CausalEdgesResult::module_outputs_read`); both LTM modes select a loop's exit port from it (`unique_module_output`).
- `db/implicit_deps.rs` -- `ImplicitVarDeps`, one per helper a parse synthesized: the helper's identity, its `capture_kind` (the phase demand the runlists read; `None` for a hoisted argument or a module instance), its reads as `DepRefs` (a module instance's are its input sources) and its typed `referenced_tables`, built by `extract_implicit_var_deps` through the same `DepScope` the parent's reads resolve through.
- `db/dep_graph.rs` -- the dependency graph and cycle gate: runlists, the dt/init cycle relation (`walk_successors`), and recurrence-SCC resolution (an SCC whose element-level graph is acyclic is compiled as one interleaved fragment instead of being rejected).
  A capture's runlists are its kind: an INIT-only capture leaves flows unless a per-step definition's current-value closure reads it, a PREVIOUS capture is never seeded into initials, and a helper's `INIT` referents are initialization roots.
  A model instantiated as a module (an explicit module's target, a stdlib template, a macro) evaluates every value-bearing variable in its initials, because a parent's initials may read any of its ports and XMILE's model is one flat graph (GH #1028).
- `db/diagnostic.rs` -- the per-model diagnostic owner `model_all_diagnostics` and the drains `collect_model_diagnostics`/`collect_all_diagnostics`.
  The payload is `crate::diagnostic::Diagnostic` (below), the salsa accumulator itself.
  - A recursive query never accumulates: `model_ltm_variables` and `model_ltm_fragment_diagnostics` return ordered `Vec<Diagnostic>` facts on their memoized values and the dependency graph returns its cycle as `ModelDepGraphResult::cycle_variables`; the owner emits each model's facts once (a parent reaches a child's LTM derivation through module scoring and layout, so a warning accumulated inside it would be reported once per reaching model).
  - The drain collapses identical rows by full equality (one fragment's two phases, one parent's per-element helpers).
  - Rows come out in the accumulator walk's order -- a memo's own rows, then each input's in first-read order: the owner's own advisories, the fragments, the cycle facts (`model_cycle_diagnostics`), the helpers, the unit pass, the wiring check and the LTM facts (`model_ltm_diagnostics`), each a tracked child read in that order.
    A source that must follow the variables' rows is a child, never a row the owner files itself.
  - A cycle is reported once, under its least member with its path read from there (`model_cycle_diagnostics`): the two phases walk different relations and may meet a loop at different members, so a loop both phases close is the same loop when its members are.
    The walks visit variables and their reads in name order, so which of several cycles is the one reported is a fact of the model (`db::diagnostic_determinism_tests::the_cycle_reported_among_several_is_a_function_of_the_model`).
- `db/units.rs`, `db/macro_registry.rs`, `db/invariance.rs` -- the unit-check pass (`check_model_units`, over a stack-local `UnitModel` view of each scope model's `model_lowered_variables`; `model_scope_models` is the module-reachable closure inference runs over, an iterative name-only worklist), the macro registry query, and run-invariance classification of flow variables: the fragment's compiler-local verdict (`compiler/invariance.rs`, a walk that treats every reference as invariant and refuses the time-dependent builtins, lagged reads, module evaluation and module inputs) joined with the variable's `Dt`/`Current` `DepRef`s and called tables, so a conditional the compiler folds keeps both arms' reads and is under-hoisted, never wrongly hoisted.
- `db/var_fragment.rs`, `db/fragment_compile.rs`, `db/layout.rs`, `db/assemble.rs` -- the fragment constructors and assembly (pipeline stages 4 and 5).
- `db/analysis.rs`, `db/ltm_ir.rs`, `db/ltm/` -- LTM (below).
- `db/exec_probe.rs` -- `ProbedDb`, the execution-count probe the incrementality tests read.
- Interned keys are collected and their slots reused: `LtmLinkId`, `ModuleInputSet` and the argument tuples salsa interns for a multi-argument query keep salsa's default `revisions`, so a key no revision has used for three is reclaimed for another.
  Salsa panics, which is an abort in a release build, if a reclaimable key's fields or memos are read without the key having been interned or validated in the current revision; no memoized value holds an interned id (every query result is `'static`), which is what keeps that from happening, and `db::interned_reuse_tests` drives edit histories that reuse slots (counting salsa's own reuse events) to hold it.

### Rules the salsa layer depends on

- A cached value is a pure function of its inputs.
  Never let `HashMap` iteration order reach a cached value or the compiled artifact: sort first (`temp_sizes_by_id`, sorted table idents in `Compiler::new`, sorted module inputs in `Var::new`, sorted runlist seeds).
  Pinned by the 12-repeat `db::fragment_determinism_tests` and `db::diagnostic_determinism_tests`, and on the surfaces a host reads by `src/simlin-tests/tests/integration/build_determinism.rs`, which opens a file twice in one process and builds every artifact from each open (saves, diagnostics, links, the wasm blob and layout, results, loop analysis): an artifact that differs took its order from a map.
  They detect an order only where it differs between two builds, so `IdentMap` and `IdentSet` draw a random key per map in every build with debug assertions (`common::IdentBuildHasher`; FxHash in a release build).
  One of them failing now and then is an order that leaked, and the fix is a sort.
- AST constants hold `ast::Literal`, compared by bit pattern, so a `NaN` literal (every stdlib template declares `initial_value = NAN`) does not defeat backdating.
  Any new float-bearing field reachable from the AST must use `Literal`; the `Eq` derives make a bare `f64` a compile error.
  The salsa inputs hold datamodel types, whose `==` compares floats bit for bit for the same reason (`datamodel::bitwise_eq!`): a lookup table holding a NaN is set once, not on every sync.
- A per-variable query needs a per-variable key.
  Reading a whole-model value (`model.variables(db)`, `ModelDepGraphResult`) from a per-variable query makes every variable recompile on any edit; go through a projection query that returns only what is needed (`var_runlist_membership`, `model_variable_by_name`, `variable_tables`).
  Whether a projection bought anything is measured, never assumed: `db::exec_probe::ProbedDb` counts every tracked query's body entries over an edit from salsa's own `WillExecute` events, because salsa backdates an equal value and keeps the memo address, so neither the value nor the pointer says whether the body re-ran.
  Gates: `db::fragment_char_tests::implicit_helper_add_is_tight_for_plain_and_module_helpers`, `module_helper_add_reparses_only_the_added_variable`, `equation_only_edit_recompiles_only_the_edited_fragment`.
- One lowering per variable.
  A variable's `Expr2` form is its memo (`lowered_source_variable`, `lowered_implicit_variable`); a consumer that needs a whole model's lowered variables assembles handles (`model_lowered_variables`, an `Arc<Variable>` per name), never a second lowering (`db::lowered_variable_tests` pins the sharing by `Arc::ptr_eq` and `ProbedDb` body counts).
  - The memo lowers under its dependencies' DIMENSIONS only (`DeclaredName::dimensions_shape`): a module instance's compiler shape is its sub-model's layout, a recursive query that a module cycle -- reachable through the unit pass -- turns into a salsa panic.
    The one map entry that is not a memo, an element-scoped helper's element-pinned projection (the read the LTM describers classify), resolves the helper's heads to the compiler's shapes, a module head's included, so the map builder takes it only where `project_module_graph(..).cycle_error_from(..)` is `None` and holds the memo's handle under a cycle, which the unit pass reads identically (`db::units_tests::a_module_cycle_reached_through_a_per_element_helper_still_unit_checks`).
- A source parse is a function of `(variable, project)`.
  `parse_source_variable` reads the variable's fields, the dimensions it names, the project-global contexts and, for a `PREVIOUS`/`INIT` subscript index, one referenced variable through its owning model's per-name projections -- never the owning model's variable set or a module instance's wiring: a model-derived parse KEY cannot backdate at all, so it re-executes every parse in the model on any edit that moves it.
  A decision that needs the owning model belongs in lowering, where `FragmentInput::deps` knows every name's kind; failing that, on the `SourceVariable` input as a field set at sync (`owner_model`, read back through `variable_owner_model`) -- never a per-variable scan of a model map.
- A module cycle drives recursive tracked queries into salsa's dependency-graph panic, which is a process abort under `panic = abort`.
  Every compile, diagnostic, and analysis entry point (`model_detected_loops` included) consults `project_module_graph(..).cycle_error_from(..)` before recursing (`db::module_cycle_tests`).
- Salsa has no input reclamation.
  Inputs are reused across syncs, never recreated, and the expanded-project slot is allocated at most once per db.
- Diagnostics derived once per project (macro-registry build error, unit-definition errors, module cycles, models known by one name) are emitted from their memoized value by `collect_all_diagnostics`, and diagnostics derived by a recursive or multiply-keyed query (the LTM facts, the dependency graph's cycle) are returned on the value and emitted by `model_all_diagnostics`: an accumulator inside such a query reports once per reachable model and is lost after an unrelated revision bump prunes the subtree (`db::diagnostic_payload_tests::every_warning_family_is_emitted_once_across_revisions`).

## Standing invariants of the compiler

- **Addresses are assigned once, at assembly.** Lowering and codegen name variables (`VarRef`); nothing before `resolve_module` knows a slot, and a `FragmentInput` carries no offset of the model being compiled.
  A cross-module reference `m·x` lowers to `VarRef { name: m, element_offset: x's slot inside the instance }` because only the sub-model's layout is fixed at that point: the module dependency's `DepKind::Module` carries that layout as a `ModelShape` (`db::model_shape`, recursively for nested instances), and `Context::resolve` is the one reader of it.
  `VarSizes` (keyed by `VarRef`, projected from the dependency shapes by `fragment::reference_extents`) is the only size information codegen reads.
- **`resolve_bytecode` is the only producer of concrete bytecode**, and it proves the VM's fixed-stack safety: a program deeper than `STACK_CAPACITY` is a compile error.
  The peephole fusions (`SymbolicByteCodeBuilder`) run before resolution and are address-independent, so resolution is a 1:1 opcode mapping; the run-invariant flow prefix length and SCC segmentation count on that.
  `Compiler` (through its `SymbolicByteCodeBuilder`) is the only producer of a `SymbolicOpcode`, so every variant of that enum (and of its `Opcode` twin) is one codegen emits; the dead-code lint, denied under clippy, enforces it -- never `allow` it on a variant.
- **Both opcode enums are tables.** `symbolic_opcode_table!` (`compiler/symbolic.rs`) and `opcode_table!` (`bytecode.rs`) hold one row per opcode: its operands and, on the symbolic side, its concrete twin; on the concrete side, its stack effect.
  An operand's type is its kind -- `SymVarRef`, `LiteralId`, `ModuleId`, `ViewId`, `DimListId`, `TempId`, `GraphicalFunctionId` with its `TableCount`, `PcOffset`, anything else data -- and `resolve_opcode`, `renumber_opcode`, `gf_run`, `var_ref`, `jump_offset`, `stack_effect` and `name` derive from the rows, so adding an opcode is one row plus its `vm.rs` and `wasmgen` arms.
  The every-row tests (`symbolic_table_tests`, `bytecode::tests`) and the merge proptest's blanking oracle derive from the same rows; `vm.rs`, simlin-wasmgen, the fusion patterns and the `db/` scans name variants by what they mean and stay hand-written.
- **A stock update is always the fused `BinOpAssignNext`.** There is no un-fused `AssignNext`; `Var::new` rejects any update whose lowered form does not end in an `Op2`.
- **An array operand is a view over storage.** Codegen accepts `StaticSubscript`, `TempArray`, `Var`, `Subscript`, and an array-valued `PREVIOUS`/`INIT` (a view over a snapshot region).
  `array_operand.rs` materializes everything else into a temp; a shape it cannot size declines and codegen reports the error.
  - Temps are per-fragment, 0-based, and recycled across sequential fragments; an interleaved SCC fragment sums them instead (`TempStrategy`).
    Within a fragment every id comes from one `TempAllocator`, issued by that one pass and final when issued: a body two or more elements read takes one id for the equation and is written ahead of the element code, and a body one element reads takes an id the elements reissue (`element_scopes`), so an equation costs one id per simultaneously-live temp rather than one per element (`db::temp_allocation_tests`).
  - The bytecode `TempId` is a `u8`: every opcode that writes a temp narrows the id with a plain `as TempId`, unguarded, while a static VIEW over a temp carries the `u32` and is rejected at resolution above 255 (`symbolic::resolve_static_view`, pinned by `test_resolve_static_view_temp_past_the_id_namespace`).
    GH #583 is that namespace; no shape in the corpus reaches it, and the write side stays deliberately unguarded.
- **No silent wrong numbers.** When a construct cannot be compiled correctly, refuse with `NotSimulatable` (VM) or `WasmGenError::Unsupported` (wasm) rather than approximate.
  A read the run makes as written but that is not a number at every step -- a subscript whose index folds to a constant naming no element, the first element of `c[Age - 1]` in an equation for every element -- is told rather than refused: `compiler::out_of_range_reads` finds it on the folded tree by the VM's own index test, and `db::fragment_compile` files one `SubscriptOutOfRange` warning per element that makes it, naming the element and spanning the reference.
  A reference whose dimensions disagree with its reader's -- an arrayed variable read where one value is needed, or a variable subscripted on more dimensions than it has -- is refused as one `MismatchedDimensions` error carrying a `common::MismatchedRead` (the variable read and its dimensions the reader has no element of), on the variable the person wrote and at the reference, whichever stage refuses it: codegen's view in a scalar position (`codegen::view_in_scalar_position`), the lowering's unpaired axes, a subscript count, a stock's flow, a module's input; a helper's refusal is its parent's (`db::fragment_compile`, which keeps a module call's argument spans for it).
  `mismatched_read_tests` rows every stage.
  The loud-safe refusals each keep their test: the stack bound, `resource_base`'s id capacity, `renumber_opcode`'s checked adds, the combiner's SCC segmentation (`db::dep_graph_tests::a_prologue_reading_an_scc_member_refuses_the_recurrence`) and `fragment_vars_in_layout`.
- **Constant folding is platform-deterministic.** `compiler/fold.rs` folds only IEEE-exact operations with the VM's own `eval_op2`; `^` and transcendentals stay runtime so the VM and the wasm blob agree bit for bit.
- **Graphical functions:** a per-element arrayed GF's tables are laid out at the element's row-major declared-dimension index (`variable::reorder_arrayed_element_tables`), because `Lookup`/`LookupArray` index `graphical_functions[base_gf + element_offset]`.
  A standalone lookup-only variable (empty or `"0+0"` equation plus a table) is a static table: excluded from every runlist, no series, and a bare reference to it is `LookupReferencedWithoutArgument`.
  `WITH LOOKUP` is value-bearing and lowers to `LOOKUP(self, input)`.
  `variable::parse_table` builds the table every lookup reads, from the points as the datamodel holds them: omitted x points are spread over the x scale, a lone point at the scale's start.
  The lookups binary-search x, so x that decreases anywhere is `BadTable` with the two values (XMILE 1.0 section 4.1.3: "the x-values MUST be in ascending order"), as is an x that is not a finite number (an infinite end extrapolates to `inf - inf`) and, for x points spread over the scale, a scale bound that is not finite or a minimum above the maximum (the reason names the scale, and a per-element table's names its element); nothing downstream of the datamodel reorders points.
  Vensim reads a lookup listed out of x order as the curve through its points (ground truth: `test/test-models/tests/subscripted_lookups`), so the MDL importer puts them in order as it reads them (`simlin_formats::mdl::convert::variables::points_in_x_order`, which a `GET DIRECT DATA`/`LOOKUPS` series goes through too).
  Neighbouring points that share an x are a vertical step and in order as they stand; each `LookupMode` reads one by the rule it reads every knot by, wherever in the table it is (at that x: the first listed point when interpolating or stepping forward, the last when stepping back), the engine's rule and the same on both backends.
  How a lookup reads its table is the opcode's `bytecode::LookupMode`, never a property of the stored table (tables are de-duplicated by their points): a plain application (`LOOKUP(t, x)`, `t(x)`, `WITH LOOKUP`) takes the mode of the table's kind (`LookupMode::of_kind`: continuous interpolates and holds the end values, extrapolate extends the end segments, discrete holds the next lower x's value; XMILE 1.0 section 3.1.4), and `LOOKUP_FORWARD`, `LOOKUP_BACKWARD` and `LOOKUP_EXTRAPOLATE` (Vensim's `LOOKUP FORWARD`/`BACKWARD`/`EXTRAPOLATE`) name their own and keep it whatever the table's kind.
  `Compiler::lookup_mode` is the one place the mode is decided: each element of a per-element graphical function is read by its own kind, and a lookup that picks its table as the model runs (a computed subscript, every element under a reducer) is refused when the tables it can reach differ in kind.
  `vm::lookup_in_mode` and `simlin_wasmgen::lower::HelperFns::lookup` are the two dispatches, and simlin-wasmgen's `lookup.rs` holds the differential test (any table, any index, every mode, VM against wasm).
  The lookups never read before a table: a search that ends at the first knot without hitting it answers with that knot.
- **A helper reads what the plain spelling reads.** A hoisted argument, a capture and a per-element helper lower under the parent's element context and dependency shapes, so they read, and are refused, exactly as the plain equation is (`db::lowering_scope_tests::a_helper_reads_what_the_plain_spelling_reads`, `a_helper_is_refused_where_the_plain_spelling_is`, `mapped_reference_semantics_tests::a_hoisted_argument_reads_what_the_plain_equation_reads`).

## Arrays

- In lowering, `ArrayView` (`src/simlin-base/src/ast/array_view.rs`) is the compile-time shape (dims, strides, offset, sparse mappings, dimension names).
  Apply-to-all equations are unrolled per element; a reference inside the body resolves each axis against the active element, broadcasting a lower-dimensional source by dimension name.
  - A subscript naming a dimension is an `IndexOp::ActiveDimRef` all the way to `compiler::subscript`, which allocates the active positions ONE TO ONE across a reference's subscripts (so `square[D,D]` under a `[D,D]` target reads the cell, not the diagonal) and resolves the element through the one mapped read; `compiler::project_var_index_to_temp` pairs a temp's axes to the variable's by the same two rules.
  - Array-producing builtins (`VECTOR ELM MAP`, `VECTOR SORT ORDER`, `RANK`, `ALLOCATE AVAILABLE`, `ALLOCATE BY PRIORITY`) and per-element arrayed-GF applies are materialized into `AssignTemp` and read back per element; whether that happens once per equation or once per element is decided by structural identity of the lowered body (`compiler/array_operand.rs`).
- `VECTOR ELM MAP` and `VECTOR SORT ORDER` follow genuine Vensim semantics, ground-truthed against Vensim output in `test/` (`vm_vector_elm_map.rs`, `vm_vector_sort_order.rs`): ELM MAP reads the source variable's full row-major storage from the base the reference establishes with no wraparound and NaN out of range; SORT ORDER ranks within each innermost row, 0-based.
- At runtime a `StaticArrayView` is resolved once per opcode (`PushStaticView`) and `ViewStorage` says which region it reads (`Curr`, `Temp`, `Prev`, `Initial`); dynamic subscripts go through `PushVarViewDirect` plus `ViewSubscriptDynamic`/`ViewRangeDynamic`.
  `BeginIter` loops evaluate elementwise bodies into temps, matching source views to the iteration by dimension id (`match_dimensions_two_pass`).
  - A view's axis therefore has to be named for the dimension it ranges over, and both statements of that name must agree: a star range `arr[*:Sub]` produces a `Sub`-named axis in `compiler::subscript::build_view_from_ops` and in `ast::Expr2`'s bounds, so the temp the reference materializes into matches its source view rather than reading NaN for every element.
  - A dimension-reordering transform on an `ArrayView` goes through one helper (`permute_axes`) because `dims`, `strides`, `dim_names`, and every `SparseInfo::dim_index` -- an index INTO `dims` -- move together; moving three of the four addresses the wrong axis (GH #1027).

## Loops That Matter (LTM)

LTM instruments a model with synthetic variables (link scores, loop scores, aggregate nodes, module pathway and composite scores) that are compiled through the same fragment pipeline as user variables and read back after simulation.
Exhaustive mode enumerates every elementary circuit; discovery mode scores every causal edge and finds loops from the recorded series after the run.
`db::model_ltm_mode` is the one gate that decides which, read by both the scored and the detected-loop surfaces.

- `compiler::fragment::FragmentInput::elementwise_target` -- `db::model_lowered_variables`, the map every LTM describer reads, holds an arrayed variable whose elements read a position they compute (an offset, `x[Age - 1]`; a condition on the element, `IF Age = 1`; a reducer whose axes the element fixes) as the equations of its elements, with every read of a variable so read pinned by `Context::pin_element_reads` to the element the compiled slot reads (not-a-number where it comes to none, the branch a decided condition takes), and a variable read only by the iterated dimensions left as written.
  The unit pass reads `db::model_written_variables`, the map without these views.
  `db::model_causal_edges` drops an edge into a described variable whose body does not read the source.
  A read through an index the model computes as it runs (`DynamicIndex`) is scored as a read of any element, with a warning that it is not exact.
  `ltm_elementwise_tests` compares generated offset chains with the same chains written element by element, loop score for loop score.
- `db/ltm_ir.rs` -- the front door: walks each variable's `Expr2` once and classifies every reference site by access shape (`RefShape`: `Bare`, `FixedIndex`, `PerElement`, `Wildcard`, `DynamicIndex`) and routing (direct or through an aggregate node).
  Every other LTM consumer reads this IR rather than re-walking the AST.
  - A dimension-named subscript is classified by the compiler's own resolution (`ltm_agg::classify_axis_access` over `DimensionsContext::executed_read_correspondence`, the projection of `resolve_mapped_read`; a subscript naming a non-active dimension is described by `mapped_read_correspondence`, and one naming a mapped subrange of the source's dimension is read through that subrange's mapping, which the pair's correspondence does not state, so `DimensionsContext::mapped_read_partner` declines it): all-iterated axes are `Bare` exactly when the two declared dimension lists reproduce the pairing the subscript spells (`db::bare_axis_pairing`, the one pairing behind `expand_same_element`, the arrayed score's admission and the dependency pins), and `PerElement` carrying the axes otherwise (shared element names under no mapping, a subrange over a superset, a transposition).
- `ltm_agg.rs` -- aggregate-node enumeration: each statically describable reducer subexpression becomes a `$⁚ltm⁚agg⁚{n}` node with a per-source `read_slice` of `AxisRead`s.
  A bare arrayed argument's slice is pass 0's pairing of its axes with the enclosing iteration (`match_axes_partial` under `DirectMappingsOnly`; whole-array with no iteration in scope or inside an array-producing builtin), so it hoists exactly as its subscripted twin does.
  - The node stores its reducer with that spelling written out (`AggNode::reducer`), which is also the synthetic dedup's identity (`synthetic_by_key`: `sum(pop)` in a scalar owner and `sum(pop[region])` under a `region` iteration are two nodes; a reducer's text is resolved to a node only among its owner's own nodes, `by_var`).
  - A per-element (`Ast::Arrayed`) slot's bare argument reads the row its element pins, and the slot's edge through it is scored as that row written out (`ltm_elementwise_tests::a_slots_bare_reducer_argument_is_scored_as_the_row_it_reads`).
    A source element no target element reads is no row (`iterated_axis_slot_elements`).
- `db/analysis.rs` -- causal edges (variable and element level; an INIT-only capture is no causal node, so no edge leads into or out of it, and a module instance's input source is an edge only where a port it binds is read per step inside the sub-model, `init_only_sources`, so a `SMTH1`'s initial-value argument is no more a causal input than a stock's initial-value equation is), tiered circuit enumeration (an edge read from a strict subset of an `Ast::Arrayed` target's slots is target-restricted, `EdgeShapesResult::target_restricted_edges`, and keeps its cycles on the element-level path with one loop per circuit), cycle partitions, detected loops (`model_detected_loops`, empty under a module cycle).
- `db/ltm/` -- generation and compilation.
  - `mod.rs`: `model_ltm_variables`, and `endpoint_dimensions`, the projection of `model_dep_shape` onto plain variables (an explicit variable's declared dimensions, a structural capture's, none for a module) read by the causal edges, the element graph, every score emitter, the loop builders and the pins -- one shape answer is not one emitter, since an element-bound helper's edge exists at one element and only `try_implicit_scalar_to_arrayed_link_scores` scores it.
  - `equation.rs`: `LtmEquation`, the typed per-arm `Expr0` a synthetic variable carries (a text generator's arm is parsed once, `LtmArm::new`; a typed generator's arm is its tree, `LtmArm::from_typed`).
    `link_scores.rs`: the emitters, each parsing its arm once and reading the completeness guard off that arm; `shaped_link_score` is the per-shape entry.
  - `loops.rs` (including cross-aggregate loop recovery), `pinned.rs` (`LOOPSCORE` pins), `compile.rs` (`lower_ltm_variable`, the one lowering of a generated equation or a generated capture under the shapes of its reads; fragment compilation; the compile-failure diagnostic pass), `parse.rs`.
  - `LtmImplicitVarMeta` is captures only: a generated equation is built from an expanded tree and mints no module instance, so the module universe under LTM is the source models' own (`db::assemble::enumerate_module_instances`).
- `ltm_augment.rs` and its `ltm_augment_*.rs` children -- the ceteris-paribus equation generators: wrap every non-source reference of the target's equation in `PREVIOUS`, pin arrayed dependencies to the element the target reads (`subscript_idents_in_expr0`, on the tree), and freeze subscript indices.
  The clock is a frozen input too (GH #1016): a changed-first partial reads `TIME` and a time-dependent call (`STEP`, `RAMP`, `PULSE`; the builtin's own `Invariance::TimeDependent`, read through `is_time_dependent_builtin`) at the previous step -- a bare `TIME` through the per-model helper `$⁚ltm⁚freeze⁚time = PREVIOUS(TIME)` (`FROZEN_CLOCK_HELPER`, minted once by `model_ltm_variables` when any arm reads it), a call lagged whole with its arguments verbatim, or left to the enclosing freeze inside a frozen dependency's subscript index -- unless the call holds an occurrence of the isolated input's live shape (the occurrence IR's verdict), in which case it stays live, clock included; the changed-last duals (`wrap_live_shaped_in_previous`, `wrap_matching_in_previous`) leave the clock live because their numerator reads every other input at `t` on both sides.
  A flow-to-stock score is the closed-form partial of the stock's synthetic net-flow aux `$⁚ltm⁚net⁚{stock} = inflows - outflows` (`generate_net_flow_equation`, minted beside the score by `shaped_link_score` and deduplicated by name), `sign * |Δflow / Δnet|` over the same `[t - dt, t]` window as every other link; the aux is not a causal node.
  Production never parses a target equation; it lowers the target's `Expr2` back to `Expr0` (`ast::expr2_to_expr0`) and consults the IR by structural path, and a target with no lowered body is declined (`PartialEquationErrorKind::MissingTypedTarget`), never scored around user text or a `0` body.
  An aggregate node's reducer is the classified `BuiltinFn<Expr2>` (`AggNode::reducer`, projected by `reducer_expr0`); `AggNode::reducer_key` is its printed identity for the dedup, the IR's routing and the wrap's matching, never an equation to parse.
- `ltm/` -- the vocabulary (`Link`, `Loop`, polarity in `types.rs`; `LoopPolarity` is the one loop-polarity type, read by the structural surface as `db::DetectedLoopPolarity`, its alias), `CausalGraph` (`graph.rs`), Johnson's circuit enumerator and Tarjan SCC (`indexed.rs`), cycle partitions (`partitions.rs`), static polarity analysis (`polarity.rs`).
- `ltm_finding.rs` with `ltm_finding_enum.rs` and `ltm_finding_fallback.rs` -- post-simulation discovery: exact union-graph enumeration, a shortest-path sampling fallback under a wall-clock and memory budget, retention against the full loop universe, and the coverage-aware cap.
- `ltm_post.rs`, `ltm_dominance.rs` -- relative loop and link scores (normalized within a cycle partition, in emission order so the IEEE sum is stable), dominant-period selection, whose periods begin and end at the run's saved rows' own times (`calculate_dominant_periods` takes them, never a cadence: a save step off the DT grid saves rows unevenly), and the dominance timeline: `strongest` is the one statement of which loop leads, at a step or over a span (the largest share, a tie going to the first of the tied), `leader_by_step` applies it at each step, `leader_timeline` cuts a run where that changes (the run-length encoding, the shortest spans joined to their longer neighbours past a maximum, a joined span led by the caller's rule over its steps, so every boundary is a change of lead), and `MeanShares` averages a share over a span's steps at which the partition is active, so a partition's shares sum to one, from running totals, so a span's mean costs one subtraction per loop whatever its length (a lead that changes at every step leaves a timeline tens of thousands of spans to join).
  A link's sign in a run is `LinkPolarity::from_runtime_scores` over its relative score, never its raw one, which is unbounded.

Rules:

- LTM is an analysis overlay, so an LTM-only failure must never masquerade as a project compile error (the overlay is an argument of every query, `db::LtmOverlay`; libsimlin's `get_errors` assesses compilability with it `Off` and harvests LTM diagnostics with it `On` only for a project that requested LTM).
  The overlay reaches a FRAGMENT through one shape only, a module instance's (the sub-model's layout, which carries its LTM section under `On`), so a fragment is keyed on it only where it resolves one: every caller of the fragment queries resolves its key through `db::var_fragment::fragment_overlay` over `fragment_reads_module`, and each constructor `debug_assert`s the predicate against the shapes it built, because an under-approximation would let an `On` assembly read module offsets resolved under `Off`.
- The describers see an element-scoped helper with every read its element pins spelled as the static index the COMPILER resolves it to (`FragmentInput::element_pinned_target`, `Context::pin_element_reads`: the helper's own fragment context running `normalize_subscript_ops` and `build_view_from_ops`), so the element graph and the scores name the slot the helper's fragment reads -- a proper subdimension, a shared-name axis or an element map included.
  Never substitute a spelling for that index: a qualified `dimension·element` of a foreign axis folds to an ordinal the compiler does not read.
- One correspondence describes every dimension-named read, plain or helper, subscripted or bare (`DimensionsContext::executed_read_correspondence`; `db::bare_axis_pairing` pairs the declared lists for a bare one, under the relations the spelling's own lowering consults -- `BareSpelling::Equation`, pass 0's `DirectMappingsOnly`, for a read in an equation body, `StockFlow`, the full context, for a stock's flows).
  - A frozen occurrence of a `PerElement` dependency keeps its subscript (`OtherDepVerdict`), since the bare spelling is a different read.
  - A reducer's bare argument that pairs with no axis of the iteration is `Wildcard`, the whole array, as `SUM(src[*])` is; the wildcard argument of a reducer the hoist declines is held live in its own edge's partial (`occurrence_realizes_shape`), the co-sources frozen around it.
  - The one executed read the describers leave undescribed is the ordinal fallback of an undeclared pair with disjoint element names at equal cardinality (GH #527); it is declined loudly, never described positionally.
- A generated equation's dependency shapes come from `ltm_dep_shape` (`model_dep_shape` plus LTM helpers and LTM synthetic variables), for a synthetic variable's fragment and a generated helper's alike, and its `Expr2` lowering runs under those shapes.
- The generated-text boundary is one place: the guard form a generator prints around its wrapped tree is parsed once, at the emitter (`LtmArm::new`); nothing upstream prints engine text to parse it again, and a helper carries no `Variable::eqn` (the generators read a target's axes off its `ast()`, keeping the `eqn` arm for user-authored source text).
- No silent wrong numbers in LTM: a link-score fragment that fails to compile is reported by `model_ltm_fragment_diagnostics` as a `Warning`, never silently stubbed to zero, and a target whose lowering failed or a read the describers cannot name is declined with a warning (`ltm_unified_tests::a_target_whose_lowering_failed_is_declined_not_scored`).
  Every LTM warning is a fact on the derivation's value (`LtmVariablesResult::diagnostics`, the fragment pass's `Vec<Diagnostic>`, `ShapedLinkScore::Unscoreable`'s payload) that `db::model_all_diagnostics` emits once per model, so a declined edge, a mode flip or a failed fragment in a sub-model is reported once however many parents instantiate it.
- LTM runs under Euler, RK2 and RK4 alike.
  A link score is a ratio of integration-step (dt) deltas reported at the saved steps: `PREVIOUS` reads the state the previous dt step ended in (the VM snapshots `prev_values` on every dt iteration, before the save/advance decision, so with save_step > dt a recorded score is the last dt step's ratio, not the saved interval's), and the VM and wasm both re-evaluate the flows at the restored end-of-step state before snapshotting it under RK, so the scores follow the method's own trajectory (`src/simlin-tests/tests/integration/ltm_integration_method.rs`: a flow proportional to its stock scores identically under all three methods; a nonlinear one does not).
  Conveyor and queue models do not participate in LTM.
  Open LTM work is organized under the `ltm` label on GitHub (epic #488).

## Special stocks: conveyors and queues

A conveyor or queue stock is not compiled directly.
`conveyor_compile::expand_conveyors` and `queue_compile::expand_queues` rewrite the datamodel into ordinary stocks, hidden container auxes, and driven flows, clearing the markers; the expanded project is synced into the db's second input slot and compiled incrementally like any other; `resolve_plans` binds the names to slots; and the VM runs the native per-step passes (`conveyor.rs`, `queue.rs`) between Flows and Stocks, interleaving a queue that feeds a discrete conveyor (`CouplingTable`).
`compile_project_incremental` rejects a surviving marker: an internal error in the main model, `*InSubmodelUnsupported` elsewhere.
Integration is Euler-only.

## Data model and identifiers

- `variable.rs` -- the compiler's variable: `Variable { ident, units, eqn, diagnostics, kind }` over `VarKind::{ Stock { init_ast, inflows, outflows, non_negative }, Aux { ast, init_ast, tables, non_negative, is_flow, is_table_only }, Module { model_name, inputs } }`, generic over the module-input type (`ModuleReference` before lowering, `ModuleInput` after) and the expression tier (`Expr0` before, `Expr2` after).
  `Aux` covers auxiliaries and flows alike -- they lower identically, one slot per element holding one equation's value, and `is_flow` only says where a stock's integration reads it.
  - `diagnostics` is a LIVE channel, not diagnostics-in-waiting: the context-free `DiagnosticError`s the parse and the lowering raised, in order (a `Unit` entry is a malformed `<units>` string and is compiled past; everything else stops the variable, `Variable::fatal_diagnostics`), which the fragment constructors turn into `Diagnostic`s.
    `model::lower_variable` is a map over `kind`, so a transformation that only rewrites equations restates no field.
- `diagnostic.rs` -- the one diagnostic payload.
  `DiagnosticError::{Equation(EquationError), Model(Error), Unit(UnitError), Assembly(String)}` is the typed error exactly as its raising site produced it, and `Diagnostic { model, variable, owner, severity, error }` is that error plus the context it is reported under -- the salsa accumulator, built at the salsa layer's raising sites (the fragment constructors, the per-model advisories, the unit pass, the LTM `ltm_warning`), where the model, the variable and the severity are known; a `Variable` carries only context-free errors and nothing between a site and the drain re-attaches context, so nothing asserts it.
  - `owner` is the variable a generated helper's row is presented under (the one it was synthesized for: a user variable, or for an LTM helper the synthetic link score); `variable` stays the helper's physical name.
  - Consumers read `code()`, `category()` (`DiagnosticCategory`: the four arms with `Unit` split by `UnitError`'s three), `location()`, `reason()` and `is(category, code)` rather than matching arms.
    The unit-inference umbrella is a `Unit(InferenceError)` filed under no variable, like every other unit diagnostic.
    An error about one element of an arrayed variable names it (`EquationError::element`, `Error::element`, read through `Diagnostic::element`): the raising site that knows the element sets it -- an element's own equation's parse (`variable::parse_equation`) and lowering (`ast::lower_arrayed_arms`, every failing arm in the dimensions' declared element order, the default's error first), its compile (`compiler::expand_per_element`), a helper lowered for it, an element with no equation, an element subscript naming nothing, a read past a dimension's end.
    The span then indexes that element's own equation when it has one, else the equation every element follows; an error of the equation every element follows that every element meets names none.
- `errors.rs` -- `FormattedError`/`FormattedErrors`, the ONE presentation adapter over a `Diagnostic`, shared by the CLI, libsimlin and the MCP servers.
  The severity word comes from the diagnostic's severity, `variable_name` is the presented variable (a helper's `owner`, else `variable`), `category` is the diagnostic's (libsimlin derives `SimlinUnitErrorKind` from it), and `details` is `Diagnostic::reason` -- an inference error's rewritten to plain language, `ErrorCode::description` when there is none, so it is always present -- handed to the FFI as `SimlinErrorDetail::details` for consumers that render the variable themselves.
  `message`'s summary line joins the code's name to the raising site's reason (`code -- reason`) in every arm, for terminals and language-model clients.

## Units

Opt-in: a model that declares units on no variable gets no unit diagnostics.
`units.rs` parses unit strings into `UnitMap`s and builds the `Context` (XMILE built-ins plus Vensim synonym groups, dropping a built-in the model redefines; of the sim specs it holds the time units and nothing else, so a parse keyed on it is not re-run by an edit of a run's start, stop, DT, save step or method); `units_infer.rs` is Hindley-Milner-style inference over the free abelian group, partial-result throughout (a conflict is confined to its connected component; macro bodies' parameter-named units lower to per-instantiation metavariables); `units_check.rs` checks each equation against declared-or-inferred units, with literal-polymorphic `MAX`/`MIN`/`PREVIOUS`/`IF` and integer-literal exponent rules.
Vensim's unit semantics are cited per rule; an unverified one is marked unverified.
`db/units.rs` is the salsa pass: inference and checking read one `Ast<Expr2>` per variable, the same lowering memo the fragment compiler borrows, through a `units_check::UnitModel` built on the stack per scope model.

## Analysis

- `analysis.rs::analyze_model` bundles compilation, LTM discovery, and dominant-period selection into `ModelAnalysis`; a model that cannot compile returns `Ok` with `analysis_error` set so "could not analyze" is distinct from "no loops".
  Its discovery step is `discover_run_loops`, which a caller with its own run under the LTM overlay in discovery mode (a what-if value, a staged equation) calls on that run's results.
- `analysis.rs::model_links` is the one owner of a model's causal links: the unique edges of `model_causal_edges` with their static polarity, macro and module internals collapsed into the links between the variables a modeler wrote (`ltm_finding::collapse_synthetic_links`) unless asked for the raw graph, and, given a run's `Results`, each link's LTM score, relative score and the sign the run gave it (`runtime_polarity`). libsimlin's model- and sim-level link queries, its wasm-results twin and the agent tools' loops all read it, so the structural and scored link sets cannot drift apart.
  The list is in `(from, to)` name order, the order of `CausalEdgesResult::edges`, an ordered map.

## Tests

- Unit tests live beside their code, either inline or in a sibling `*_tests.rs` mounted with `#[cfg(test)] #[path]` so `use super::*` still resolves.
  The integration tests, benches and examples are [simlin-tests](/src/simlin-tests/CLAUDE.md).
  `test_common::TestProject` is the model builder, exported behind the `test-support` feature for sibling crates' tests.
- There is one compiler, in tests too: a test that needs a variable's lowered `Expr2` reads `db::lowered_source_variable` (or `model_lowered_variables` for a model's worth), a test that needs its compiled form reads it through the production per-variable lowering (`TestProject::flow_exprs`, over `db::var_fragment::explicit_fragment_input` + `compiler::fragment::lower_fragment`), a test that needs a refusal's location reads `TestProject::error_diagnostics`, and a loop-discovery test drives `ltm_finding::discover_loops_with_graph` with the graph and context `analysis::analyze_model` builds.
  Never add a whole-model parse, lowering or compile path for tests to compare against: it is a second implementation that every compiler change then has to be made in twice, and it can only agree with the production one by construction where the two share code.
- What pins unit semantics is the unit suites over production diagnostics, and what pins sharing is `Arc::ptr_eq` against the production memos plus `ProbedDb` body counts (`db::lowered_variable_tests`).
  A fixture is what production produces: build models through `TestProject`, `open_xmile` or `open_vensim` and read results through the production queries.
- The `test/` corpus at the repo root holds models with expected outputs from other SD tools.
- A test too heavy for the default suite is a gate: `#[ignore = "<what it sweeps>; run under the gates profile"]`.
  `#[ignore]` means exactly "needs an optimized build", so every ignored test passes under `scripts/gates.sh` (the `gates` cargo profile: optimized, with debug assertions and overflow checks), which CI's `gates` job runs on every push to main and every pull request to main; a test that records a known defect asserts the defect in the default suite instead.
  The corpus sweeps and the C-LEARN and World3 gates are gates.
  The default suite's budget is CPU-seconds on four cores, which rayon hides from a test's wall time (`docs/dev/rust.md`); test a threshold with a test-only override, not a fixture large enough to trip it.
- `scripts/gates.sh` runs the ignored tests only, of every crate that has any; it builds with the `ext_data` feature (the Excel data provider) on and also runs that feature's tests (`data_provider::`), which no default build compiles.
