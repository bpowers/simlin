# Vensim MDL Parser

Pure Rust reader and writer of Vensim MDL files: it reads a file into a `datamodel::Project` and writes a project back as MDL.

For global development standards, see the root [CLAUDE.md](/CLAUDE.md).
For build/test/lint commands, see [docs/dev/commands.md](/docs/dev/commands.md).
For the design and the Vensim format notes, see [docs/design/mdl-parser.md](/docs/design/mdl-parser.md).

## Module Map

### Parsing Pipeline
- `lexer.rs` -- Hand-written `RawLexer` for MDL tokens (context-free)
- `normalizer.rs` -- `TokenNormalizer` for context-sensitive transformations (function detection, section tracking)
- `parser.rs` -- Recursive descent parser producing AST
- `ast.rs` -- AST types: `Expr`, `Equation`, `Lhs`, `LookupTable`, `SubscriptDef`
- `reader.rs` -- `EquationReader`: drives parser, captures comments, handles macros
- `builtins.rs` -- Vensim built-in function recognition via `to_lower_space()` canonicalization
- `settings.rs` -- Post-equation settings section parser (integration type, unit equivalences), and the names of the custom graphs, tables and reports a file defines between its sketch and its settings

### Conversion (`convert/`)
- `mod.rs` -- Main conversion orchestration, group building, `DataProvider` threading
- `control.rs` -- The control variables, folded to the sim specs' numbers where their equations are constants
- `variables.rs` -- Variable type detection (stock/flow/aux) and building; EXCEPT default_equation handling, GET DIRECT resolution.
  - **Element keys are canonical** (`canonical_element_key`, over `CanonicalElementName::from_subscript`, as every reader of a datamodel stores them); the spelling of an element is its dimension's, which is what the writer writes.
  - **A variable's dimensions are the dimensions of the elements its equations define** (`settle_dimensions`, the one owner for a variable and its synthetic net flow, over `dimensions::axis_dimension`): per axis, a dimension a left-hand side names that holds exactly the defined elements, else the smallest declared dimension holding them all, the first declared of several that size (GH #1059). That Vensim runs a variable whose equations define only some elements of a dimension over those elements is Vensim's (`test/test-models/tests/except_subranges`, whose `my var2` Vensim saves over X and Z only); which of several dimensions holding them it is over is Simlin's rule, since Vensim keeps no dimension per variable. An axis no declared dimension holds leaves the variable unarrayed. Rows: `convert/axis_dimension_tests.rs`.
  - **An `:EXCEPT:` default fills no element**: it applies only where every element has a slot, so an excepted element nothing defines stays undefined (the engine's rule, unverified).
  - **A number list defines the elements its left-hand side does, less those it excepts, one number each, in order** (`convert/number_list_tests.rs`). A list of another length, or one no element takes numbers from, is refused: which number an element would take is a guess. Whether Vensim refuses such a list is unverified.
  - **An element's name as a value is its position**, written `Dimension.Element` in the dimension that owns it, the largest (`xmile_compat`'s `element_value`, `convert::element_owners`; `convert/element_value_tests.rs`).
  - **A single apply-to-all MDL equation imports as one `Equation::ApplyToAll`**, not as N identical per-element slots. A dimension name in an expression is the element's 1-based position, which only an apply-to-all equation has an active dimension for, so `y[DimA] = VECTOR ELM MAP(x[three], (DimA - 1))` compiles only in that form. The collapse is gated by `slots_are_one_apply_to_all` plus a `single_apply_to_all` precondition: ONE source equation with no `:EXCEPT:`; not backed by external data (the whole opaque `{GET ...}` family, `external_data::is_external_data_placeholder`: a resolvable one's slots agree only as a property of the spreadsheet, and an unresolvable one leaves an empty equation in every slot, which `ApplyToAll(dims, "")` turns into an `EmptyEquation` error); no slot with an INITIAL equation or a graphical function (`ApplyToAll` has nowhere to put either); and slots covering the dimensions' full cartesian product. The INITIAL, graphical-function and coverage clauses are each load-bearing (dropping one reds its own test); the `:EXCEPT:`/default/equation-text clauses are belt-and-braces, since `needs_substitution` is exactly `expanded_eqs.len() > 1 || has_except_eq`. The rule is a stricter form of the one [mdl_equivalence.rs](/src/simlin-engine/tests/integration/mdl_equivalence.rs)'s `normalize_equation` applies when comparing against xmutil (which collapses on slot agreement alone), so anything the importer collapses the harness does too. Rows: `convert/apply_to_all_tests.rs`; corpus gate `simulate::simulates_vector_mdl_genuine` (`vector.mdl` against real-Vensim `vector.dat`).
  - **An empty right-hand side is no equation** (`""`), the same as a lookup-only table's.
- `stocks.rs` -- Stock/flow linking via is_all_plus_minus algorithm and the synthetic net flow
- `dimensions.rs` -- Dimension/subscript building with range expansion and `DimensionMapping` construction; `axis_dimension` and `smallest_dimension_holding`, the reader's dimension rule, which the writer asks too
- `external_data.rs` -- GET DIRECT DATA/CONSTANTS/LOOKUPS/SUBSCRIPT resolution via `DataProvider` trait
- `macros.rs` -- Converts each `:MACRO:` block into a macro-marked `datamodel::Model` (via `datamodel::Model::new_macro`); the conversion pipeline is reused per macro body
- `multi_output.rs` -- Materializes `:`-list multi-output macro invocations at import (using the Pass-6 macro-marked models' `MacroSpec`s)
- `types.rs` -- Internal types (`SymbolInfo`, etc.)
- `helpers.rs` -- Utility functions (units, expressions)

### Views (`view/`)
- `mod.rs` -- Main view parsing: `parse_views()` entry point
- `elements.rs` -- Element line parsing (types 1, 10, 11, 12); a record of any other type (an image, 30 or 31) is kept on the view as a `SkippedRecord`
- `types.rs` -- View types: `VensimView`, `VensimElement`, `ViewError`
- `convert.rs` -- `VensimView` -> `datamodel::View` conversion
- `processing.rs` -- Coordinate transforms, angle calculation, flow points

### The reader resolves a file one way

On every run, in one process or many: element ownership among dimensions of one size goes to the one declared first, alias dimensions follow declaration order, a per-element equation's dimension the LHS does not name takes its element through the first LHS dimension, in the LHS's order, that it maps to or from, or through a dimension resolved that way (`build_element_context`; GH #859), and the variables are built in name order, so the import's error is the first failing variable by name. Never let a `HashMap`'s iteration order decide anything an import returns: each map takes its own random seed, so the decision differs between two imports of one file in one process. Gate: `import_determinism_tests::every_corpus_file_imports_one_way` (ignored, release; every corpus `.mdl` imported 13 times, with and without its data), and `a_file_imports_one_way` in the default suite.

### What the reader does not keep

`parse_mdl_with_warnings` (the crate root's `open_vensim_with_warnings`) returns the project `parse_mdl` returns, with an `ImportWarning` for each kind of thing the file holds that the project does not keep, so a host can say at open what a save would lose. What a modeler put on a sketch view is reported view by view, since where it sat is part of what it was (`SketchLosses` in `view/convert.rs`): comments, graphs, sliders, other input/output objects and images. What follows from what the diagram does not draw is reported once over the whole sketch (`SketchConsequences`): the drawings of Time and the control variables, arrows drawn to anything not kept, records of an unknown type. A cloud is never a loss, even one no kept flow ends in: it holds nothing, and the writer draws a cloud wherever a flow it writes needs one, so a file Simlin saved would otherwise report its own clouds. Then come the custom graphs, tables and reports (`settings::custom_outputs`). Vensim stores an input/output object as a comment record with bit 4 of `bits` set and its kind in `tpos` (`VensimComment::io_object`, after Vensim's documented sketch format). Tests: `import_loss_tests.rs` (a sketch holding one of each) and [tests/integration/import_losses.rs](/src/simlin-engine/tests/integration/import_losses.rs) (World3).

### Expression Formatting
- `xmile_compat.rs` -- XMILE-compatible expression formatter (function renames, argument reordering, name formatting, per-element subscript substitution). Its restructuring arms for builtin-named calls run before macro resolution, so a like-named macro cannot shadow them.
  - The output is **equation text our own lexer reads back**, so a variable REFERENCE is spelled by `XmileFormatter::quote_reference`, which delegates to `ast::needs_quoting` -- the same predicate `ast::print_ident` and `ltm_augment::quote_ident` use -- so a name holding `'`, `$` or an equation keyword (`IDch15d.mdl` declares `MOD`) reads back as the name (GH #976). **`nan` is the deliberate exception**: the importer stores Vensim's `A FUNCTION OF(...)` placeholder as the equation text `NAN`, so quoting `nan` would bind that placeholder to any like-named variable, and the writer cannot spell it otherwise either -- `A FUNCTION OF` "is not intended for use in writing equations, and precludes simulation" (vensim.com/documentation/fn_a_function_of.html). A bare `nan` reference naming a declared variable therefore reads as the NaN literal (`keyword_ident_tests::a_bare_nan_reference_in_mdl_is_still_the_literal`); changing that means changing how the importer represents "no equation". A zero-argument builtin's name (`dt`, `pi`, ...) is quoted where the model declares a variable of that name (`Theil_2011.mdl` has `dt = TIME STEP`), so the reference reads the variable, and left bare otherwise, the builtin (the engine's reading, unverified against Vensim). `quoted_space_to_underbar` is the separate DEFINITION-side spelling (a `datamodel` ident, not equation text).
  - **PULSE and PULSE TRAIN** expand to the comparisons Vensim documents: PULSE is on while Time plus half a TIME STEP is strictly between start and start plus width, and a width of 0 is TIME STEP (vensim.com/documentation/fn_pulse.html); PULSE TRAIN repeats that every interval up to `end`, inclusive, each pulse at least one TIME STEP long (fn_pulse_train.html, and Vensim's own run in `test/sdeverywhere/models/pulsetrain/pulsetrain.dat`). Rows simulated in `pulse_tests.rs`; the writer recognizes each expansion as its call (`recognize_pulse`, `recognize_pulse_train`).
  - **INTEGER and MODULO** import as the engine's `TRUNC` and `REM`: Vensim's truncate toward zero (fn_integer.html, fn_modulo.html; ground truth `test/test-models/tests/rounding/output.tab`), where XMILE's `INT` is the floor and `MOD` the floored modulus. For a divisor at or below zero `REM` is 0 (the engine's rule, unverified). A two-argument `MOD(a, b)` call of a name the model does not define is the floored modulus `(a) MOD (b)`, which is how the writer spells it.
- **`xmile_compat` does NOT parenthesize by precedence, deliberately.** `mdl::parser`'s *binary* precedence table disagrees with both Vensim and XMILE: it puts `+`/`-` at the lowest level and `:AND:` above the comparisons, so it builds `1 + (2 > 2)` and `2 > (1 :AND: 0)` where Vensim means `(1 + 2) > 2` and `(2 > 1) :AND: 0` (GH #914). Emitting the operands flat lets the XMILE grammar re-establish the intended grouping, which is why C-LEARN reproduces `Ref.vdf`; faithfully parenthesizing the MDL AST keeps the wrong grouping and breaks C-LEARN (measured: 49239 tolerance violations). The laundering is sound only where XMILE's precedence matches Vensim's *for the operators `xmile_compat` emits*: `and` above `or` in both (`parser::parse_logical` is an or-level wrapping an and-level; `mdl::tests::logical_precedence_survives_the_mdl_to_xmile_laundering`), and `^`, whose grouping flat text cannot recover, is grouped (`paren_exponent_operand`). One residual laundering cannot fix: both parsers bind `:NOT:`/`not` tighter than a relational operator, so `:NOT: 1 > 2` evaluates to 0 where Vensim gives 1 (#914).

### Writing (`writer.rs`, `writer_arrayed.rs`)

`project_to_mdl` / `project_to_mdl_with_warnings` (re-exported from the crate root as `to_mdl` / `to_mdl_with_warnings`) serialize a `datamodel::Project` back to Vensim MDL.

- **Context-aware expression printer.** `MdlPrintVisitor` walks each `Expr0` threading a `WriterContext` (built per model by `WriterContext::from_model`, `with_written_names`) that carries the model's variable idents and the names their definitions are written under, each arrayed variable's declared dimensions, the project's dimensions, and the extrapolating lookups. It resolves what a context-free printer cannot:
  - **wildcard subscripts** (#847): `SUM(a[*])` where `a` is declared `a[DimA]` is `SUM(a[DimA!])`; a star-range `*:Dim` is the same `Dim!`; a position with no declared dimension is a bare `*`.
  - **`pi`** (#850): Vensim has no `PI` builtin, so `pi` is written as the literal `3.141592653589793`.
  - **a variable named for a 0-arity builtin** (`dt`, `pi`, `time`, ...): a zero-argument `App` is the builtin, written as Vensim's keyword (`TIME STEP`) or, for `pi`, its value; a reference to the variable is a quoted `Var`, written as the variable's name -- so `dt = TIME STEP` is written as it was (`keyword_ident_tests`).
  - **INITIAL arity** (#852): `init` is `INITIAL` (1-arg) or `ACTIVE INITIAL` (2-arg); a 2-arg `normal` is the 5-arg `RANDOM NORMAL`.
  - **An element's own initial** is written as its ACTIVE INITIAL; only an element without one takes the variable's `compat.active_initial`.
  - **Numbers** are written by `xmile_compat::format_number`, the importer's own spelling, which reads back to the same `f64` bit for bit (`a_number_reads_back_bit_for_bit`; `any_number_reads_back_bit_for_bit`, ignored, over 3000 random numbers).
  - **Functions**: each builtin is written under a name the reader knows (`xmile_to_mdl_function_name`; every entry of `builtins::BUILTINS` has a row in `every_builtin_the_reader_knows_is_saved_as_it_reads`). `TRUNC` is `INTEGER`, `REM` is `MODULO`, a one-argument `MAX`/`MIN` (the reduction) is `VMAX`/`VMIN` and `RANK` is `VECTOR RANK`, as Vensim names them (fn_vmax.html, fn_max.html, fn_vector_rank.html). A call of PULSE or MODULO is the builtin whatever variables the model names, so it is written as what it computes. A function Vensim does not have -- `ROUND`, `INT` (the floor), `MEAN`, `PREVIOUS` -- is written by name with a warning: the reader reads it back as itself, and Vensim will not read it. The writer never lowers such a call to Vensim primitives (a composition repeats the argument, wrong for a stochastic one, and rests on unverified edge semantics, GH #610). The floored modulus is `MOD(a, b)`, read back as the operator; in a model that names a variable `mod` it is `MODULO` with a warning.
  - **Recognizers** of the importer's expansions (PULSE, PULSE TRAIN, QUANTUM, LOG 2-arg, SAMPLE IF TRUE, ALLOCATE BY PRIORITY, TIME BASE, RANDOM POISSON, RANDOM 0 1), each the exact inverse of its `xmile_compat` arm, and native lookup-call syntax `table ( input )`.
  - **Grouping**: `written_shape` plus `ast::paren_if_necessary`, the one grouping rule `print_eqn` uses too, keyed on the XMILE/Vensim precedence table (not `mdl::parser`'s, #914); an `IF`, the `MOD` operator and a recognized expansion are written as calls and need no grouping.
- **Names.** A display newline in a name is written as the `\n` escape inside a quoted name, as Vensim writes one (`format_mdl_ident`; `test_special_variable_names.mdl`), and the reader keeps the escape. A reference is written as its variable's definition spells it (`WriterContext::reference`), since the reader matches names as written and the engine's names fold a break into the space around it. A view element is named as its variable is (`views_named_as_defined`): a Stella diagram may break a name its variable does not have. A name holding `'` after its first character is written bare, as the lexer reads it.
- **Arrayed variables** (`writer_arrayed.rs`). An element equation names no dimension, so the writer names the dimensions wherever the equations allow, else the reader would infer them from the element names alone: an array of numbers over every element is the number list naming its dimensions (`x[DimA] = 1, 2, 3`; for three dimensions or more, one list of the last two per element of the leading ones, as Vensim writes it); otherwise elements are grouped under a left-hand side naming a dimension wherever every element equation agrees across it; a variable with an `:EXCEPT:` default is an `:EXCEPT:` equation over its dimensions, or over a subrange of one the default names, followed by the elements it excepts and those outside it (`except_equations`) -- never an equation that defines no element: a default no element is (one naming a mapped range, say) is written as element equations with a warning that the default is not kept. Each key part is written as its dimension spells the element (`WriterContext::declared_element`), entries in canonical key order (`order_arrayed_entries`). A variable defining only some elements of its dimensions is read back over the dimensions of exactly those elements (the reader's rule above), and the writer warns. Residual, a limit of the format: elements that differ, over a dimension sharing its elements with one declared earlier, read back over the earlier one (`writer_arrayed_tests`).
- **Free-text sanitization choke point** (`sanitize_free_text`, #849). Every modeler-authored free-text sink (variable units/documentation, group name/doc, `22:` unit-equivalence tokens) routes through one function, so a structural character cannot terminate a construct early and re-parse the remainder as phantom variables. It maps `|` -> `/` (non-whitespace, so a field-final `|` cannot become a trim-sensitive trailing space), the four section-terminator runs -> space, and per-field separators (`~` in units, `,` in a `22:` token) -> space. Line endings normalize to LF; the single LF->CRLF pass runs once at the end of `write_project`. The **units** field is a unit *expression*: sanitization keeps it structurally safe but cannot make arbitrary text a valid unit, so such units fail re-import loudly.
- **Export warnings** (#856). `project_to_mdl_with_warnings` returns `(String, Vec<ExportWarning>)`; warnings never change the emitted text. `Err` is reserved for structural impossibilities (>1 non-macro model, an ordinary non-macro `Module` variable, an unreconstructable macro-invocation cluster). The warning arms are listed on `project_to_mdl_with_warnings`: an unparseable equation (written as raw text, #912), the transpose operator (#913), a function Vensim does not have, a floored modulus forced to MODULO, a dropped `non_negative`, conveyor/queue markers (#887), Discrete and unmarkable Extrapolate tables (#854), a one-to-many element mapping no dimension names, an arrayed variable defining only some elements, an `:EXCEPT:` default that cannot be written, multi-word group names and group docs, and loop metadata. The CLI prints them to STDERR.
- **Values Vensim cannot hold**: a NaN (the reader's form of `A FUNCTION OF`) is written as `NaN`, and an ACTIVE INITIAL anywhere but the top of an equation (Vensim: it "must appear first on the right of the = sign", fn_active_initial.html) as itself; each with a warning.
- **External data** placeholders (`{GET DIRECT ...}`, `is_external_data_placeholder`) are written verbatim, without a warning: they are opaque by design.
- **Extrapolating lookups** (#854). MDL marks a table extrapolating only by a `TABXL` call site, so a `LOOKUP` call of a standalone extrapolating table is written as `TABXL`; a table with no call site, or an inline `WITH LOOKUP`, warns.
- **The settings section** follows the main model's sim specs (`write_settings_section`). The control variables are written in the model's own Control group, under the name and documentation the model gives it, and with the ungrouped variables where it has none.
- **A dimension sharing its elements with another** is kept where an equation can name it (a number list, a group of agreeing elements, an apply-to-all equation); otherwise the elements alone read back over the first declared such dimension, and `check_save` reports it.

### Tests

- `writer_tests.rs` (unit), `writer_lossiness_tests.rs` (what a save loses, and its warnings), `writer_xmile_tests.rs` (functions and names a model read from XMILE holds), `writer_fixpoint_tests.rs` (each rule that makes a save a fixed point), `writer_sketch_tests.rs`, `writer_arrayed_tests.rs`, all mounted `#[cfg(test)] #[path]` to stay under the per-file line cap.
- `subscript_rule.rs`: Vensim's rule that a subscript range on a right-hand side is on the left-hand side or mapped onto one there (ref_subscripts.html, ref_subscript_mapping.html), as a check over MDL text. Every corpus source holds it; the corpus save gate and `first_save_is_a_fixed_point` hold every save to it.
- `writer_proptest.rs`: free text never corrupts the variable set; `equation_write_reparse_is_fixpoint` (`parse(print(e)) == e` on the AST; its generator keeps to arithmetic, the operators where `mdl::parser`'s table agrees with Vensim's -- widen it when #914 lands; the full operator set is `ast::print_eqn_proptest`); and `first_save_is_a_fixed_point` over generated equations and rich models (arrays over dimensions and subranges with applied and unapplied defaults and per-element initials, stocks and flows, lookups and calls, `WITH LOOKUP`, groups, awkward numbers), with and without a generated view: the save reads back as every variable, element, equation, initial and table generated (`reads_back_as_generated`), holds the subscript rule, and is a fixed point. A generator makes only what MDL can hold (a two-argument `INIT` only at the top of an equation).
- `save_roundtrip_tests.rs`: every corpus `.mdl` read, saved and read again is the datamodel it was, up to `normalized` (views, equation spelling as parsed trees, an unapplied `:EXCEPT:` default, variable order) -- `a_save_keeps_the_datamodel_over_the_corpus` (ignored, release; `EXPECTED` lists the files whose save changes the datamodel, and is empty) and `a_save_keeps_the_datamodel` in the default suite.
- `writer_output_idempotence_ratchet` holds `write(parse(write(parse(x)))) == write(parse(x))` for every re-parseable corpus `.mdl`, and `clearn_save_is_a_fixed_point` holds C-LEARN to it in a release run. The rules behind it:
  - **Connector points.** `LinkSketchCompat::control_point` keeps the point the sketch gave a connector, written back while it still reads as the link's shape between the endpoints written (`connector_control_point`, through the importer's own `view::processing::connector_shape`); a moved or reshaped link gets the arc's rounded bisector point. Multi-view composition stacks views by their extents, which include connector points, so a point that moved on save would move every later view.
  - **Pipe ends** snap along their own segment (`resolve_flow_ends`); a side the model gives no stock takes the pipe end its connector's field 4 marks for it (Vensim's sketch format, vensim.com/documentation/24305.html) when the view does not draw the other side's stock.
  - **Flows across views.** A cloud the importer places after the views merge (`routes`) is written with its flow, and a flow end on an element its segment holds no record of is written into a cloud (`CutEnds`): an MDL pipe names an element of its own view, and the importer routes the flow to its stock again.
  - **Sketch uids** are dense per segment (`SketchUidRemap::dense_for_segment`), every record its own.
  - **The save step** is written as it was read: one that follows the time step (`SAVEPER = TIME STEP`, one the importer cannot evaluate, or none) imports as no save step and is written as `TIME STEP`; a number is written as that number.
- The first save normalizes what the datamodel does not hold: a flow label's own position (written at its label side's default offset) and a control variable the importer cannot evaluate (written as its value).
- Integration: [tests/integration/mdl_roundtrip.rs](/src/simlin-engine/tests/integration/mdl_roundtrip.rs) (whole equations, arrayed models included); [tests/integration/mdl_vensim_truth.rs](/src/simlin-engine/tests/integration/mdl_vensim_truth.rs) (the reader against Vensim's own runs, release; `mdl_vensim_truth_series.tsv` pins each differing file's differing series, rewritten by `UPDATE_VENSIM_TRUTH_SERIES=1`); [tests/integration/save_meaning.rs](/src/simlin-engine/tests/integration/save_meaning.rs) (saves every corpus model in every format, asks `save_check` what each save changes, and lists every save that does not keep its model with the cause: the format cannot hold it, or a writer or reader defect).
