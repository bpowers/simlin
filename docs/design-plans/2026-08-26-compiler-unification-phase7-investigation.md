Companion to `2026-08-25-compiler-unification.md`. This is the enumeration
Phase 7 ("Pure parse; captures and AST-carried implicit modules") required
before any code moved: every decision `builtins_visitor.rs` and its callers

exists as equation text or is identified by its name, the salsa keys involved,
the runlist contract a capture must reproduce, and the LTM and stdlib paths

## 0. What the evidence says, in one screen

1. `builtins_visitor.rs` makes sixteen distinct decisions (Section 1). Exactly **three** read model-level state that is not project-global: D1 "is this ident module-backed" (reads `module_idents`), D2 its pre-classification `collect_module_idents`/`equation_is_module_call` (re-parses every Aux/Flow equation in the model, `model.rs:416-495`), and D3 "is this bare subscript index a non-shadowed element" (reads `model_var_names`, LTM path only). Everything else reads project-global inputs (dimensions, macro registry, macro-body owner) or nothing.
2. D1 is the one that re-keys every parse (`query.rs:245-283`, interned `ModuleIdentContext`), and **its correctness payload is smaller than its documentation claims.** The rustdoc at `builtins_visitor.rs:471-486` already shows codegen's `static_slot` (`compiler/codegen.rs:101-108`) accepts a `m·port` reference without a helper; a stdlib-call aux such as `delayed = SMTH1(x, 99)` is a one-slot scalar (its AST becomes `Var($⁚delayed⁚0⁚smth1·output)`, `variable_size` = 1), so `PREVIOUS(delayed)` does not need a helper either; and the stdlib-model extension (`stages.rs:211-238`) is documented as inert ("no shipped stdlib body calls PREVIOUS/INIT"). The residual D1 covers is an arrayed module output port, "which no model in the corpus produces" (`builtins_visitor.rs:482-483`), and a bare `PREVIOUS(sub)` of an explicit module, which is ill-defined with or without the helper (the helper copies slot 0 of the instance). The decision can move to lowering wholesale: emit a capture iff the lowered argument is not `static_slot`/`snapshot_static_view`-addressable, which is the predicate codegen already enforces (`compiler/codegen.rs:1280-1300`).
3. There are **four** different module-ident contexts in production today, not one: the empty `ModuleIdentContext::new(db, vec![])` (every analysis/LTM/layout/libsimlin dependency read: `db/analysis.rs:1615`, `db.rs:601`, `db/ltm/loops.rs:51`, `db/ltm/pinned.rs:297`, `db/ltm/mod.rs:292`, `layout/mod.rs:4579`, `src/libsimlin/src/model.rs:510,740`), the model's own set (`model_module_ident_context(.., vec![])`: diagnostics, implicit-var info, LTM reconstruction), the per-instance set widened by module-input names (`var_fragment.rs:205,573`, `fragment_compile.rs:580,727`, `dep_graph.rs:195`), and the stdlib-extended set (`stages.rs:259-274`). A fifth, LTM's own `HashSet`s (`db/ltm/mod.rs:360-401`), is not a `ModuleIdentContext` at all. Consequence: on every LTM/analysis path each variable is parsed **twice** (empty context and model context), and the dependency sets the causal graph sees can differ from the ones the compiler schedules (Section 3.3).
4. A synthesized helper is printed to text exactly twice (`builtins_visitor.rs:885,929` for captures; `:1033` for stdlib/macro args) and re-parsed at **seven** production sites (Section 2.3). Its name is its identity at **twenty-one** places (Section 2.4), including the `Results` offset map and the LTM causal graph surfaced through libsimlin.
5. The runlist/layout contract a capture must reproduce is small and exact (Section 4): a PREVIOUS capture is a flows-only unit with no edge from its parent in either phase; an INIT capture is seeded into initials through `all_init_referenced`, keeps the parent->capture **initial** edge, loses the dt edge, and is also (wastefully) recomputed in flows. Byte-identical runlists additionally require the capture's runlist ident to **sort identically** to today's `$⁚{parent}⁚{n}⁚arg0[⁚{suffix}]` name, because every runlist is a lexicographic sort tie-broken by DFS visit order (`dep_graph.rs:2316-2320, 2567, 2363-2462`) and the implicit layout section is name-sorted (`layout.rs:66-69`).
6. AC3.1 will **not** flip by deleting `ModuleIdentContext` alone. `compile_var_fragment` clones the whole `model_module_map` value (`fragment_compile.rs:143`), which gains an entry when any implicit module instance is added (`query.rs:747-762`); that re-executes every fragment in the model independently of the parse key. The pinning test's stated reason (1) -- "`project.models(db)` changes when `stdlib⁚smth1` is spliced" (`fragment_char_tests.rs:2675-2677`) -- looks stale: stdlib models are spliced unconditionally on every sync and `set_models` fires only on a changed map (`db/sync.rs:712-721, 746-753`). This needs measuring before Phase 7 chunk 4 is planned (Open question 1).

Notes on the table:

- D1's documented rationale and the code disagree in two places worth recording so they do not steer the design. (a) `model.rs:553-558` says a stdlib module input "has no persistent slot in prev_values"; but a module input is compiled to `LoadModuleInput -> AssignCurr` in both initials and flows (`fragment_compile.rs:337-353`), so it does have a `curr` slot and therefore a `prev_values` slot. (b) `model.rs:547-551` says stdlib-call Aux/Flow variables "occupy multiple slots"; in the salsa pipeline the call is rewritten to a reference to a separate implicit module instance (`builtins_visitor.rs:1075-1080`) and the aux keeps `variable_size` 1 (`layout.rs:54`). Neither claim was verified by running anything; both are contradicted by the code cited.
- D3 today has two answers for the same equation depending on path (user parse: helper; LTM parse: no helper) -- `prev_init_tests.rs:401-510` pins all three arms. Moving the decision to a shared predicate removes that asymmetry and would change the user-path artifact (fewer helpers) -- a ledger row with an explanation, and the `prev_init.txt` golden changes.
- D5/D6 are the only decisions where today's parse is *guessing* because it lacks information lowering has. They are the strongest argument for the design doc's "captures are lowered through `lower_fragment`" shape.
- D7-D9 read `project_macro_registry` and `macro_body_owner`, both keyed on `SourceProject` only, so they are compatible with a `(var, project)` key. D8 is the one place the parse needs "which model owns this variable"; the reverse map answers it without a model key.

## 4. Ordering semantics a capture must reproduce

### 4.1 How the visitor rewrites the parent

`PREVIOUS(e)` gets a `0` fallback (`builtins_visitor.rs:1181-1188`, also at `ast/expr1.rs:214-220`). For `PREVIOUS(a0, fb)`/`INIT(a0)` (1211-1264): if `a0` is a `Var` that is not module-backed, or a `Subscript` whose base is not module-backed and whose every index is static or dimension-spanning, it stays; otherwise `make_temp_arg` replaces it with `Var("$⁚p⁚n⁚arg0[⁚suffix]")` (scalar helper, 915-943) or `Subscript("$⁚p⁚n⁚arg0", [dim·elem ...])` (arrayed helper, 842-913). The helper's own equation is the printed argument. Expr1 lowering maps `previous`/`init` to `BuiltinFn::Previous(a, fallback)`/`Init(a)` (`ast/expr1.rs:214-221`); codegen emits `SymLoadPrev { var }` after walking the fallback, or `SymLoadInitial { var }`, and refuses anything that is not a `static_slot` (`compiler/codegen.rs:1278-1307`).

### 4.2 How the helper and parent are classified

`ClassifyVisitor` (`variable.rs:1266-1429`): inside `Previous(arg, fb)` the direct `Var`/`Subscript` arg ident goes to `previous_referenced` (1352-1355); `arg` is walked with `in_previous`, `fb` with `in_init` (1357-1365). Inside `Init(arg)` the walk sets `in_init` (1367-1372). `record_ident` puts an ident seen outside PREVIOUS into `non_previous`, and outside both into `non_init` (1322-1332). Derived: `previous_only = previous_referenced - non_previous`, `init_only = init_referenced - non_init` (1472-1481); `init_referenced` is filled only when `in_init && !in_previous` (1344-1346, 1398-1400). `isModuleInput` branch selection happens here when `module_inputs` is `Some` (1411-1421), which is why `variable_direct_dependencies` is keyed on `ModuleInputSet`.

`build_var_info` (`dep_graph.rs:184-378`) then strips: `dt_deps -= keep_dt_dep-filtered stock-port reads` (292-321), `dt_deps -= dt_init_only_referenced_vars` (322), `dt_deps -= dt_previous_referenced_vars` (323), `initial_deps -= initial_previous_referenced_vars` (325); `normalize_dep` collapses `m·x` to `m` (213-226). Implicit helpers get identical treatment from `ImplicitVarDeps` (345-377). `all_init_referenced` collects every `init_referenced_vars` (339-343).

### 4.3 The resulting contract for a PREVIOUS capture `C` of parent `p = PREVIOUS(e, fb)`

1. `C`'s ident appears in `p`'s equation exactly once, inside PREVIOUS, so it is in `p`'s `previous_only` in **both** classifications (the init classification runs over `p.ast()` when `init_ast` is `None`, `variable.rs:163-172`, `query.rs:369-374`). Therefore `p -> C` is stripped from `dt_deps` (323) and from `initial_deps` (325): **the parent carries no edge to the capture in either phase.** Pinned: `fragment_cache_tests.rs:182,292` (`test_previous_lagged_feedback_*`), `prev_init_tests.rs:9,78`.
2. `C`'s own deps are `e`'s references, classified with the same rules (so a nested `PREVIOUS`/`INIT` inside `e` strips its own lagged reads: `prev_init_tests.rs:78`), filtered by `keep_dt_dep` (a `m·stock` read is not a dt edge; `dep_graph.rs:292-312`), normalized by `normalize_dep`.
3. Runlists: `C` is a non-stock, non-table-only var, so it is in **flows** (2590-2610) and in **stocks** never; it is in **initials** only if it is transitively reachable from a seed through `initial_dependencies` (2500-2551). `p -> C` is not an initial edge, so a PREVIOUS capture reaches initials only via its own seeding clause (`dt_deps.is_empty() && !initial_deps.is_empty()`, e.g. `PREVIOUS(INIT(x))`), never via `p`.
4. Runtime: `LoadPrev` reads `prev_values` (snapshot of `curr` after each step, `vm.rs:1120,1196,1247`) and returns `fb` while `use_prev_fallback` is set -- the whole initials phase and the first flows step (`vm.rs:994-997, 1609-1613`). So the within-step position of `C` relative to `p` is irrelevant; what matters is that `C` is evaluated every step after its own deps.
5. A2A per-element captures (`Ast::ApplyToAll` with a module call or PREVIOUS/INIT) are `N` scalar units `$⁚p⁚n⁚arg0⁚{elem}` (D14), each wired as above; the arrayed GH #541 capture is one `ApplyToAll` unit `$⁚p⁚n⁚arg0` referenced as `helper[dim·elem]` per element (`builtins_visitor.rs:899-912`), whose stub needs its dims at every consumer (`query.rs:518-527`, `var_fragment.rs:376-425`, `fragment_compile.rs:962-1023`).

### 4.4 The contract for an INIT capture `C` of parent `p = INIT(e)`

1. `C` is in `p`'s `init_referenced` and `init_only`. `build_var_info` strips `p -> C` from `dt_deps` (322) but **keeps it in `initial_deps`** (only `initial_previous_referenced_vars` is stripped there). Pinned: `fragment_cache_tests.rs:592,660,712,775,833,889`.
2. `C` lands in `all_init_referenced` (339-343) and is therefore a **seed** of the initials runlist (2508-2522: `|| all_init_referenced.contains(n)`), with `e`'s references pulled in by the transitive closure (2527-2551). The kept `p -> C` initial edge orders `C` before `p` in initials when `p` is there too, which is load-bearing: during initials `LoadInitial` reads `curr`, not the snapshot (`vm.rs:1609-1613`, `ChunkRegions::backing` 546-553), so `C` must already have been assigned.
3. `C` is **also** in the flows runlist (it is a plain aux) and recomputed every step although nothing reads its flows value. A capture design that omits it from flows is a correct artifact-shape change (fewer flow opcodes) and must be reported in the ledger (AC1.3) with the `prev_init.txt` golden re-baselined.
4. `p` itself, when `p = INIT(x)` bare or `INIT(e)` via a capture, has empty `dt_deps` after the strip and non-empty `initial_deps`, so `p` is seeded into initials by the "fully determined at initialization" clause (doc 2480-2499, code 2517-2519; GH #584). Pinned: `src/macro_expansion_tests.rs:779`.

### 4.5 What byte-identical runlists additionally require

Every runlist is `topo_sort_str` over a **lexicographically sorted** candidate list with DFS-visit-order tie-breaking (`dep_graph.rs:2316-2320` `var_names` sorted; `:2567` `init_list` sorted; `:2363-2462` `topo_sort_str`). The implicit layout section is name-sorted after the explicit one (`layout.rs:66-69`), `calc_flattened_offsets_incremental` likewise (`db/assemble.rs:2413-2414`), and `assemble_module` iterates `implicit_info.keys()` (`:1399`) while `FragmentMerger` renumbers resources in runlist order (engine CLAUDE.md stage 5). So a capture filed under a **different** synthetic ident (say `$⁚p⁚c0`) sorts differently, moves in the runlist, and changes literal/GF/view ids -- a legitimate but ledger-reported artifact change. Filing captures under the exact `$⁚{parent}⁚{n}⁚arg0[⁚{suffix}]` string, with `n` assigned in the same argument-first walk order (`builtins_visitor.rs:1097-1098` walks args before the call) and the same shared-`n`-per-module rule (`:998-1078`: arg helpers and the module share `n`, then one increment), keeps the runlists and layout byte-identical. Recommend doing that in chunk 2 and deciding separately whether to change names.

- Classification: `is_stdlib_module_function` = `delay|delayn|smthn` or any `stdlib::MODEL_NAMES` entry (`builtins.rs:1135-1138`). `stdlib_args` is the single statement of port order (`module_functions.rs:77-88`: `smth1/smth3/delay/delay1/delay3/trend -> [input, delay_time, initial_value]`, `npv -> [stream, discount_rate, initial_value, factor]`); `stdlib_descriptor` wraps it as `ModuleFunctionDescriptor { model_name: "stdlib⁚{name}", parameter_ports, primary_output: "output", additional_outputs: [], is_macro: false, passthrough: None }` (`:330-344`).
- Expansion (`expand_module_function`, `builtins_visitor.rs:982-1080`): macro arity is strict (`:990-994`, stdlib lenient); instance name `$⁚{parent}⁚{n}⁚{func}[⁚{suffix}]`; a `Var` arg wires `src = ident` (after `substitute_dimension_refs` in A2A, `:1008-1017`), any other arg becomes aux `$⁚{parent}⁚{n}⁚arg{i}[⁚suffix]`; `dst = "{module}.{port[i]}"`; the call is replaced by `Var("{module}·{primary_output}")`. `rewrite_alias_module_call`'s `init_expr = input.clone()` (`:125`) means `DELAYN(input_expr, t, 3)` hoists the same expression twice (`arg0`, `arg2`) -- the `ImplicitInputSrc` contract can dedupe to one capture, which changes artifact shape (ledger).
- `MacroRegistry::build` (`module_functions.rs:378-597`): pass 1 descriptors + passthrough classification (parses the primary-output body, `:294-320`), pass 2 macro/model collision, pass 3 recursion over **re-parsed body text per formula** (`:613-680`, `equation_formulas` `:691-705`), pass 4 no module inside a macro (cycle safety for `project_module_graph`, `:437-563`). Build failure yields an **empty** registry, load-bearing for cycle safety (`db/macro_registry.rs:184-211`). All project-keyed; compatible with a `(var, project)` parse key.
- `is_renamed_builtin_macro_collision` = `{init, previous}` or `is_stdlib_module_function` (`module_functions.rs:125-189`), shared by the recursion scan (`collect_called_macros`, `:736-787`) and the visitor (`builtins_visitor.rs:419-426`). `enclosing_model` comes from `macro_body_owner` (`db/macro_registry.rs:308-343`).
- The `isModuleInput(initial_value)` idiom: `stdlib/smth1.stmx:19`, `smth3.stmx:19,23,30`, `delay1.stmx:16`, `delay3.stmx:16,36,41`, `trend.stmx:16`. `BuiltinFn::IsModuleInput(ident)` (an `Ident` arg, design doc Phase 1) selects the live branch at classification time from the instance's `ModuleInputSet` (`variable.rs:1411-1421`), which is why `model_dependency_graph`, `compile_var_fragment` and `assemble_module` are keyed on the instance's input set and why the same `stdlib⁚smth1` model compiles to distinct modules per distinct `dst` set (`enumerate_module_instances`, `db/assemble.rs:2133-2151`; `db/incremental_compile_tests.rs:1267` `test_incremental_compile_distinguishes_module_input_sets`). An unwired trailing port (`SMTH1(x, t)` with no initial value) leaves `initial_value` out of the set, so the template's `else input` branch is the live one; the unit checker relies on this grouping too (`db/units.rs:309-345`).
- What `ImplicitModule { id, model_name, inputs: Vec<(ImplicitInputSrc, dst)> }` must carry to replace today's `datamodel::Variable::Module`: `model_name` (descriptor), ordered `dst` port idents (`parameter_ports[i]`, bare -- today's `{module}.{port}` prefix is stripped again by `build_module_inputs`/`enumerate_module_instances_inner`), each `src` as `Var(Ident)` (possibly dotted `m·out`, possibly a qualified `dim·elem` after A2A substitution -- an edge `resolve_module_input` would reject and `build_module_inputs` accepts) or `Capture(id)`, the A2A element identity (today the `⁚{suffix}` in the name; one instance per element is unavoidable because the engine has no arrayed module instance), the `primary_output` the call is replaced by (macros: the macro's own name; multi-output invocations are the MDL importer's explicit `Variable::Module`, not this path), and for dependency purposes the fact that **every** src is both a dt and an initial dep of the instance (`db/implicit_deps.rs:55-73`) while the instance is a sink in the cycle relation (`dep_graph.rs:148-150`) whose transitive set readers do not absorb (the module branch of `compute_inner`, `:1942-1950`, and its `!d.is_module` absorption guards). Readers of `{module}·{stock}` get no dt edge (`keep_dt_dep`, `:292-312`; `smth1`'s `output` is a stock, `stdlib/smth1.stmx:17-20`, which is the C-LEARN #591-c1 case in the comment).

## 7. Risks and sequencing

1. **Chunk 2 (captures for PREVIOUS/INIT) should hold names and walk order fixed.** Do the identity flip (`(parent, id)`, AST-carried expression, `FragmentInput` constructor) while deriving the runlist/layout ident by the exact old rule (Section 4.5). Then the `fragment_char` goldens (`prev_init.txt`, `modules.txt`, `recurrence_scc.txt`), `fragment_determinism_tests`, `diagnostic_determinism_tests`, `combined_fragment_tests::assembled_init_combined_fragment_is_byte_stable_across_fresh_dbs`, `dep_graph_tests::initials_runlist_is_deterministic_across_fresh_databases` and the wasm parity corpus stay byte-identical and any diff is a defect, not a shape change. Changing names, dropping INIT captures from flows (4.4.3), keeping `ApplyToAll` instead of rewriting to `Arrayed` (D14), or eliding bare-element captures on the user path (D3) are each separate, ledger-reported shape changes; recommend sequencing them after AC3.1 flips, not inside chunk 2.
2. **Decide D1/D3 at one place consumed by both the dependency stage and lowering.** Whether a `PREVIOUS(arg)` is a direct lagged slot read or a capture determines the dependency graph (a capture is a unit with its own deps; a direct read is a `previous_only` strip on the parent). Today both are decided in the parse, so they agree by construction. After the move, the dep stage (Phase 8 `DepRef`) and `lower_fragment` must call the same predicate on the same lowered form, or the graph and the bytecode drift -- the same failure class as GH #568's two dependency walks. Suggest: the predicate is "does the argument lower to `static_slot`/`snapshot_static_view`", computed once from the capture's lowered expression and exposed as a per-variable projection.
3. **AC3.1 needs `model_module_map` firewalled, not just `ModuleIdentContext` deleted.** `compile_var_fragment` clones the whole map (`fragment_compile.rs:143`) and `compile_implicit_var_phase_bytecodes` likewise (`:1106`); its value changes whenever an implicit module is added (`query.rs:747-762`). Without a `module_target_by_ident(model, project, ident)` projection, `implicit_helper_add_is_tight_but_module_helper_add_is_not` stays saturated after chunk 4 and the test's failure will be misread as a parse problem. Also check whether reason (1) of that test is real (Open question 1).
4. **Three parse contexts collapse to one, and some behaviour lives in the differences.** The analysis/LTM paths parse under the empty context (Section 3.3) and see different `dt_previous_referenced_vars` than the compile path for `PREVIOUS(module-backed)`; `pinned.rs:280-296`, `db/ltm/mod.rs:280-304` and `analysis.rs:1611-1617` each comment on reproducing "the old no-arg path exactly". After unification those comments are wrong and the normalisation they describe may become unnecessary or may change LTM causal edges (a synthetic helper node appears or disappears in the graph libsimlin surfaces, `src/libsimlin/src/analysis.rs:86-94`). Run the LTM corpus and `ltm_char_tests` as the gate, and expect `db/tests.rs:1315,1455` and `simulate_ltm_pinned.rs:1703,1846,1907` to be sensitive.
5. **Tests that pin the mechanism rather than the semantics and will need deliberate rewriting**: `fragment_determinism_tests.rs:533` `a_cross_context_helper_name_collision_is_confined_to_a_failing_compile` and `:1041` `an_implicit_helper_declines_when_the_contexts_synthesize_different_sets` (their premise -- two contexts synthesize different sets -- dissolves; the second says so explicitly at `:1100-1104`); `:648` `an_active_initial_that_collides_a_helper_name_is_refused` (D15); `stages_tests.rs:736,774` (interned-context identity); `model.rs:1286-1376` (`collect_module_idents`/`equation_is_module_call`); `builtins_visitor.rs:1513,1529,1544,1597,1629` (dedup, substitution, print-reparse -- the two GH #913 tests should survive as value tests of `SMTH1` argument evaluation even though the mechanism they name is gone); `variable_dimensions_tests.rs:80` (oracle parses under the empty context); `db/tests.rs:15,26`, `dimension_invalidation_tests.rs:27`, `fragment_cache_tests.rs:639` (call the old signature); `prev_init_tests.rs:401` (calls `parse_var_with_module_context` with `model_var_names`); `implicit_diag_tests.rs:51` and `diagnostic_determinism_tests.rs:270` (message text "implicit variable '{name}' (synthesized while parsing '{parent}')", `fragment_compile.rs:640-650`); `dep_graph_tests.rs:2288` `synthetic_helper_symbolic_fragment_is_parent_sourced` (resolves a helper by `$⁚` name through `model_implicit_var_info`).
6. **Suites that must stay green throughout**: `tests/integration/simulate.rs` (incl. `simulates_init_builtin` 1683, `simulates_previous` 1759, `simulates_step_into_smth1` 1769, `helper_recurrence_mdl_synthetic_helper_in_scc_simulates` 3880, `simulates_passthrough_init_macro_*` 4027/5006, the `simulates_macro_*` block 4688-5333), `simulate_systems`, `mdl_roundtrip`, `simulate_ltm*.rs`, `ltm_array_agg.rs`, `wrld3_unit_errors.rs` (stdlib unit grouping), `src/rk_integration_tests.rs:211-558` (PREVIOUS fallback semantics under RK), `src/array_operand_materialization_tests.rs` (array PREVIOUS/INIT routes), `src/macro_expansion_tests.rs`, `metasd_macros.rs`, the wasm parity corpus, and the four determinism/golden suites named in item 1.
7. **Sequencing suggestion**: keep the design doc's four chunks but split chunk 3 into 3a (stdlib `ImplicitModule` with per-element expansion and shared `n`) and 3b (macros + passthrough + #554), and add to chunk 4 the `model_module_map` projection and the deletion of the empty-context twin calls in analysis/LTM/layout/libsimlin/cli (Section 3.2-3.3) -- those call sites are where `ModuleIdentContext` is constructed, so `rg ModuleIdentContext src/` cannot be empty (AC2.4) until they are rewritten to the new `variable_direct_dependencies(var, project, ModuleInputSet)` key.
